Status: evidence only; no native implementation or manifest coverage. The removal capture is `porting/generated/maps-wind-sampling-deps/_adhoc/0x141dd61e0__141dd61e0.c` (SHA-256 `e33227932d36023e4b5b0f65bbfb4db1db44c0e867e2c84c924db6aa03c60267`). Its decompiler had parameter ID and stack analysis disabled.

`0x141dd61e0` first calls `0x141dccda0(node, bounds, child_output)` and saves the returned child count, before examining local entries. The node begins with a pointer to entries at +0 and an int32 count at +8. Entries are 0x18 bytes; an int32 at entry +0x14 is compared to the int32 pointed to by the second parameter. It scans in ascending order and removes only the first local match. For a non-last match it copies the entire last 0x18-byte entry into that slot, then decrements the node count; it does not shrink or free the allocation in this capture. On a local miss it visits the selected children in output order, recursively, stopping after the first successful child. No merging, rebalancing, or node deletion is visible here. The child's success is read as a byte, although the decompiler emits a `void` return for the function; the actual return ABI and value on all paths require machine-code verification before expressing this as a typed function. The stack buffer appears to hold four child pointers, but the selection routine, traversal rules, node links and invariants are not captured; do not infer their layout or child count guarantees from this alone.

The sampling caller `porting/generated/maps-wind-impulse-lifecycle/_adhoc/0x141ddfad0__141ddfad0.c` lines 775–791 passes the pointer at manager +0x2e0 as the spatial root, an address of the responder index, and a local 2D box assembled from responder bounds X/Y minima and maxima with validity set to 1. This spatial store is shared state: a flat responder array operation is not a substitute for selecting and mutating the correct tree node.

The insertion wrapper `porting/generated/maps-wind-responder-deps/_adhoc/0x141dd0bb0__141dd0bb0.c` (SHA-256 `e907592c205369dd2775a6b7e22f2bb6b2ab54ef281c5b71d9c8741158d213d0`) calls the structure a quadtree in its diagnostic. Until those are recovered, keep the sampling draft's spatial operations as required external effects, passing a 2D box and nullable source label through an eventual correctly typed contract. ## Engine template correspondence

The local engine source `/opt/fortnite/UnrealEngine/Engine/Source/Runtime/Engine/Public/GenericQuadTree.h` provides `TQuadTree<ElementType, NodeCapacity>`. The captured warning text, fallback label, bounds comparison and unconditional recursive insert match its `Insert` exactly. The removal capture matches its `Remove` and `RemoveNodeForElement`: select quads first, scan local nodes for the first equal element, `RemoveAtSwap` without shrinking, then recurse in selected order until success. The engine source declares the return `bool`; the capture independently shows a byte-valued success flowing between recursive calls, but its final return ABI still needs verification. For `int32`, the template's `FNode` (`FBox2D`, then element) explains the observed 0x18-byte stride and element offset +0x14. The engine class fields also account for the observed +0 nodes, +0x10 four child pointers, +0x30 box, +0x44 position, +0x4c minimum size and +0x50 internal flag; the corroborating construction capture below makes this stronger than a layout guess. These correspondences support an `int32` quadtree specialization, but do not alone establish every template body or its template argument in the client binary.

Registration capture `porting/generated/maps-wind-actor-ingress/_adhoc/0x141dd4d50__141dd4d50.c` lines 241–290 lazily allocates 0x58 bytes, zeroes the array and four children, sets a valid square box from `-0.5 *` to `+0.5 *` the first runtime value on both axes, initializes its center, sets the +0x4c float to the second runtime value converted through int32, clears the +0x50 byte, and inserts the responder index and projected XY bounds. The two values come from virtual calls through globals `0x14812a8e8` and `0x14812a900`; their identities and runtime values remain unresolved. In particular, the source constructor's default minimum of 100 is not evidence for this instance. The template default capacity is 4, but the recursive insertion capture establishes that this client specialization uses 16: it checks `Nodes.Num() < 0x10` and logs capacity 0x10.

The engine template specifies that insertion places elements intersecting multiple children at the current node, splits full leaves when squared box size exceeds squared minimum size, and redistributes single-child elements on split. Its `GetElements` appends intersecting local nodes in array order before visiting selected children; `GetQuads` selects inclusive boundaries in bottom-left, bottom-right, top-left, top-right order. The new captures corroborate these selection, insertion and query behaviors: `0x141dccda0` selects inclusive center boundaries in bottom-left, bottom-right, top-left, top-right order; `0x141dbcf90` appends intersecting local elements in ascending array order, then recursively visits those children; `0x141dd0e40` uses the same single-child/multiple-child handling, squared size threshold and 16-entry capacity. The insertion capture delegates splitting to a helper; that helper is compared below. Swapped removals can alter later local iteration order. The template's slow duplicate check is an assertion, not runtime deduplication.

For integration, use the engine template as the candidate shared representation as `TQuadTree<int32, 16>` with the recovered initialization and runtime configuration sources; preserve the registration-sampling-query shared tree and original ordering. The existing sampling draft's `FBox` and `int32` insertion flag contract should instead eventually project to `FBox2D` and accept a nullable `const TCHAR*` label, as the captured call's zero is a null label. This note does not change the draft. No builds or tests were run.

Split helper `porting/generated/maps-wind-tree-lifetime/_adhoc/0x141ddd750__141ddd750.c` corroborates `Split`: it allocates four 0x58-byte children in top-left, top-right, bottom-left, bottom-right slots, with the same center/extent-derived boxes as the template. Each child starts empty and non-internal and inherits the parent +0x4c minimum size. It marks the parent internal, walks the original nodes in order, appends each single-quadrant node to that child, and retains the other nodes in parent order. The retained case includes zero selected quadrants in the capture, whereas the template asserts a positive count before retaining non-single-quadrant nodes; this matters only for input violating that assertion in an assertion-enabled build. This comparison supports direct use of `TQuadTree<int32, 16>` for the recovered tree behavior, provided the same construction values and shared ownership/lifetime are integrated. The source declares `Remove` as `bool`, and recursive byte success in the capture corroborates that signature despite its decompiled `void` declaration.
