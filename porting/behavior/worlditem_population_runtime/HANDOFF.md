# World item population investigation

`EntryHelpers.h` contains source equivalents of 0x142038870 and 0x142038ae0, suitable for adaptation into the existing generator architecture. They are not integrated or compile-tested. 0x142038870 calls 0x142ca0820 and returns its result, then destroys its by-value string. 0x142ca0820 dispatches on lengths 32, 36, 38, 68, 35 and 22 to ParseExact; this matches the local UE 4.25 `FGuid::Parse`. The caller ignores the return value. The parse writes directly to the existing GUID and there is no rollback. 0x142038ae0 sets weak ParentInventory and the byte at entry +0x66, reflected `bIsReplicatedCopy`.

The outer 0x142060e40 remains **unclosed**. The profile cast is specifically UFortMcpProfileWorld (class getter 0x1429ae020), not the base profile. Store it as a weak profile at object +0x230, and store the result of 0x1421d8de0 as the existing `NativeOwningController` weak pointer at object +0x78. The profile getter 0x1421d8de0 calls profile virtual +0x150, enumerates a weak-object list from 0x14468fb70, returns the first AFortPlayerController whose +0xac0 equals profile +0xa8, else null; the list's semantic API and comparison types are not closed. Both weak assignments precede every guard. Profile +0x290 is reflected `FortInventory`.

Object +0xd2 is `bPendingPersistentDelete`: true returns success. Otherwise, when the profile exists, 0x14254c270(profile, by-value ItemId) checks two lookup tables inside the first element at profile +0x150, only when array count +0x158 > 0; either hit returns success immediately. This helper's state types and lifecycle remain unresolved. Next, `bNeedsPersistentUpdate` (+0xd1) true logs a warning (category 0x148134920) and returns success. That logging path dereferences the stored weak profile without checking for null, and calls world-item virtual +0x470 for the string; preserve rather than invent safe defaults.

Then get profile FortInventory, if present. A non-null inventory with actor role byte +0xf0 unequal 3 returns false; this matches `GetLocalRole() != ROLE_Authority`, not `InventoryType`. Assign `OwnerInventory` only after that guard. If `TemplateId` is nonempty (FString Num > 1), resolve it with the already-integrated asset manager lookup, cast to UFortWorldItemDefinition; missing/wrong type logs `Failed to find ItemDefinition for WorldItem with Template %s!` at LogFort warning and returns false. If it is equal to the existing ItemEntry.ItemDefinition, return success immediately before changing the entry. Otherwise assign it. With empty template retain the existing definition. Set `bLoadedFromSave` (object +0x80 bit 0); parse ItemId into ItemEntry.ItemGuid, ignoring result; assign ItemEntry.Count = Quantity; invoke NativePopulateItemAttributes. False returns immediately, with prior changes retained. On success set ParentInventory to OwnerInventory with bIsReplicatedCopy false, and call 0x1420397e0.

0x1420397e0 checks weak ParentInventory validity, calls 0x14201d4c0(parent, &entry) if valid, and then sets bIsDirty true even if the call did nothing. 0x14201d4c0 is not a simple notification: it first checks actor authority. For non-replicated copies it obtains the entry GUID via 0x14202eda0, rejects invalid GUID, finds the corresponding entry in inventory's map at +0x340, copies via 0x142025400, sets the destination's +0x67 bIsDirty false, and marks that destination in the fast array at inventory +0x228 (0x140719c10). For replicated copies it directly performs fast-array MarkItemDirty on the supplied entry, including replication IDs/keys and array bookkeeping. Both successful branches call 0x14201de90. The map's proper typed ownership, copy semantics, and last helper remain unresolved; replacing them with a generic update is incorrect.

After 0x1420397e0, an inventory calls 0x142015840(inventory, world item). This returns unless inventory byte +0x3fc is set; obtains the item's GUID from virtual +0x468; if valid and the inventory GUID map has a non-null matching value, returns; otherwise invokes inventory virtual +0x630. Without an inventory the outer function invokes item virtual +0x318 twice and passes `(true, first == 1, second == 9, false)` to 0x142027b30. That helper broadcasts both native and dynamic OnItemChanged delegates, with optional diagnostics (false in this call). The native delegate has not been reconstructed; broadcasting only the reflected dynamic delegate loses listeners. These are substantial remaining dependencies; no partial outer body is proposed for integration.
