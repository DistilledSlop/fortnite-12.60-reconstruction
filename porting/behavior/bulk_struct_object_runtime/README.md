# Embedded reflected struct object-pointer getters

`python3 porting/behavior/bulk_struct_object_runtime/prepare.py` scans the native function inventory against the SHA-256-pinned original runtime image named in the script and writes evidence and proposed manifest entries to `/tmp/gameplay-bulk-struct-object/`. It requires Capstone at `/tmp/common-input-capstone`. It does not modify the canonical manifest or generated headers.

Only parameterless object returns with the exact raw object property and return flags are considered. A complete inline, direct-call, or uniquely proven virtual wrapper and complete pointer-load leaf must match. The reflected class, embedded struct and member must resolve uniquely; both reflected object types must resolve to the same class, and generated declarations must be actual raw pointer fields. The scanner verifies the generated struct include and cross-module dependency/export where applicable, rejects existing maintained/generated functions, and records metadata and instruction evidence in the report. This excludes weak, soft and subclass wrappers and does not infer downcasts.

On the pinned image the scan examined 23,758 inventory records and produced two proposals: `AFortAttachableProjectileBase::GetAttachedToActor` reads `AttachedInfo.AttachedToActor` at `0x868 + 0x90`, and `AFortPlayerPawn::GetVehicleActor` reads `VehicleStateLocal.Vehicle` at `0x1578 + 0`. Both return `AActor*`. Rejections include 217 unmatched complete leaves and eight non-unique or unverified generated struct members. A virtual dispatch was also unproven (included in unmatched leaves). The original image and generated reflection remain the reproducible evidence; these results are proposals pending integration.
