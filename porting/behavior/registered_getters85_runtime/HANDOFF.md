No generation, build or runtime tests were run. `source-pins.json` records input source hashes at assessment time; generated headers are also consulted and may change during integration.

`report.json` includes rejection reasons, full getter bytes inherited from the source scanner, class interval and neighbor evidence, and 24 registration mappings with actual builder bytes. The scanner follows at most one direct no-register jump, confirms the unique reflection block/name mapping, validates the UTF-16 class literal in RDX, uses objdump to reject intervening RDX writes or control flow, and takes size/alignment exclusively from immediate stack argument stores immediately before the exact registration helper call. A scanned class is accepted only if its entire proposed field lies in its own registered interval after the immediate parent, and generated inheritance and strict occupancy/struct extent checks succeed. Parent and own occupancy must both be known. Canonical and batch84 pending getter names are excluded. Candidate proposals cannot overlap each other. The script does not modify canonical sources.

A float result whose original exec copies bits through EAX uses a raw `uint32` member and `FMemory::Memcpy` to return float; this asserts no original storage type. Most proposals are exact plain-byte reflected Bool reads under the existing prior scalar policy. These follow the existing `bulk_native_scalar_runtime` policy for valid native bool representations 0 and 1; arbitrary or corrupt-byte parity is not claimed. The other proposals are Int dword reads.
