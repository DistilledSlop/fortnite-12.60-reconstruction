# Objective-stat row post-serialization blocker

`FFortQuestObjectiveStatTableRow` is a 184-byte, 8-aligned `FTableRowBase` derivative (reflection block `0x147b914e0`, struct ops `0x142abacf0`, vtable `0x1464ff590`). The reflected fields include `Condition` at `0x70`, `TemplateId` at `0x80`, `AlternateTemplateIds` at `0x90`, and `bIsCached` at `0xa0`. The remaining 16 bytes at `0xa8` are a native shared pointer and reference controller, not a reflected property. Its native destructor/copy/initialization must preserve their ownership correctly.

Struct ops slot 10 advertises `HasPostSerialize`; slot 11 is `0x142abe0f0`, a thunk moving the struct pointer to RCX and jumping to `0x14244bcc0`. That body checks bit 0 of archive byte `0x28` (consistent with UE 4.25 `FArchiveState::ArIsLoading`) and byte `0xa0`. On loading when not cached, it calls `0x142439210` with validation enabled and sets the cached byte to 1 only if that call succeeds. It does nothing otherwise. Captures are in ignored `porting/generated/quest-row-post-probe{,2}`; probe transactions rolled back, though Ghidra reported project metadata changes.

`0x142439210` clears the shared cache for empty `Condition`. Otherwise it retains the existing cached expression if the expression's stored string equals the current condition; if not, it invokes `0x14240d370` and assigns its returned shared pointer. With validation enabled, it invokes `0x142414d50` to extract tag references, and requests each gameplay tag with error reporting disabled (`0x143e96810` -> `0x143e96870`, whose capture identifies `UGameplayTagsManager_RequestGameplayTag`). It returns false if any request returns `NAME_None`, and true otherwise; it checks all returned tags. The exact parser, cache object semantics, extraction, failures, logging, constructors, destructor and copy behavior remain unported. `0x14240d370` is a 1,275-byte function containing the diagnostic `Failed to parse quest condition %s: '%s'!`; `0x142414d50` is a 640-byte expression traversal. Captures are in `quest-row-post-probe3` and `quest-row-post-probe4`.

Integration needs generator support to promote the row, include its correct base and dependencies, emit its native shared state and copy/lifetime behavior, and install `PostSerialize` plus `TStructOpsTypeTraits<...>::WithPostSerialize`. The current `render_struct_header` in `porting/gen_native_classes.py` emits reflected fields and selected policy hooks, with no generic recovered post-serialization splice. Merely generating the reflected row or setting `bIsCached` is not faithful. The quest query manifest entries remain blocked until this complete dependency is implemented and validated. This investigation did not build or test runtime behavior.
