`0x14110e120` is the actual installation/replacement routine. If profile `+0xd8` is nonnull it invokes its virtual slot 0 with argument 1, and the destructors at `0x1410efb60` and `0x1410efba0` show that this destroys and frees the old backing. If profile byte `+0x92` is nonzero, it allocates 0x338 bytes, constructs the base with `0x1410ec490`, initializes additional fields, installs derived vtable `0x145bfcca8`, and stores the result at `+0xd8`; otherwise it allocates 0x198 bytes and installs the base constructor result. Allocation failure stores null. It also resets profile `+0xc8` to zero and `+0xc0` to -1. Callers include `0x141106ef0` and `0x1421f3d30`. The identity of byte `+0x92` is not proven by the reflection dump's unresolved bool offset.

Base constructor `0x1410ec490` installs vtable `0x145bfcc38`; both slot 0x28 values were read directly from the captured image. Base target is `0x1410fe1c0` and derived target is `0x1410fe220`. The base target passes the original key in R8 to `0x1407be140` with map at backing `+0x58`. On an index other than -1 it returns the address of the value at slot +0x10 (slots stride 0x28); otherwise null. The key is the FString produced by the separately recovered `NativeGetProfileKey()` item-definition function. The returned header is borrowed from the map and is invalidated by relevant backing destruction or mutation; the original caller consumes it synchronously.

The derived target first searches a key collection at `+0x2e8`. If the key is not present it searches the cache map at `+0x298`, returning its value when found, otherwise calls `0x1410fe160(backing+8, key)`. If the key is present it removes it from `+0x2e8`, calls `0x1410fbda0(backing, key, temporary array)`, and either removes the cache entry and falls back to `0x1410fe160` when the call returns zero, or finds/adds a cache value and copies the temporary array into it when nonzero. The temporary array is destroyed before return. Its 16-byte elements have object pointer first and control-block pointer second; cleanup decrements non-atomic strong count at control block +8, calls its virtual 0 when zero, then decrements weak count +0xc and calls virtual +8 with argument 1 when zero. This establishes shared-control-block behavior and non-atomic reference counting for this temporary, though the C++ template typedef and the source entry's complete concrete type are not established. The derived destructor `0x1410efba0` destroys the cache before base destructor `0x1410ed670` and frees the backing on deleting-destructor argument 1.

The original investigation did not yet recover recomputation or comparison; the subsequent closure below supplies both. Population and invalidation/mutation integration remain necessary. No canonical, Native, generator, build, runtime, test, or commit changes were made.

## Further closure and source proposal

`0x1410fe160(backing+8,key)` is exactly the same base lookup in map backing `+0x58`. `0x1410fbda0` first clears its output, looks up that base array, and returns zero if absent. For each base entry it extracts the FString at entry `+0x10` and searches the overlay map at backing `+0x198`. `0x1410fa050` uses a shared-string key and compares its text case-sensitively. A missing override copies the base shared entry. A matching override increments a match counter and copies the replacement shared entry only when replacement `+0x30` is greater than zero. It returns the match count. Thus zero matches means use the original base array, whereas one or more matches caches the recomputed array even when it is empty. The array assignment helper `0x1409f5600` increments non-atomic strong counts of its copied 16-byte entries, confirming the cached result owns shared references independent of the temporary array. `0x1410ebe70` and `0x1410ebf10` establish that the entry contains FString fields at +0, +0x10 and +0x20, quantity at +0x30 and UObject pointer at +0x88. `0x141104980` assigns +0x88 through a UObject-creating virtual call, and installs a weak reference to the shared entry in the resulting object; `0x1410f1290` reports the pointer for GC. Exact class names and the complete entry representation remain unresolved.

`0x1407be140` and dirty-set lookup `0x140ace810` use comparator `0x142bcf780`: ASCII case folding, but unequal non-ASCII UTF-16 code units are compared directly. The overlay entry-ID lookup is case-sensitive. Verify the selected native FString map/set key functions preserve the former behavior before integration; do not accidentally use case-insensitive entry-ID lookup. `ProfileBackendLookup.proposal.h` implements the recovered algorithm with typed non-thread-safe shared pointers, explicit entry and overlay adapters, and backing-owned result arrays. It is a logical proposal, not a claim of binary layout or a complete profile update implementation. Integration must connect the real population, GC collection, overlay updates and dirty marking; absent those paths, it is not a drop-in runtime implementation. No builds or tests were run.
