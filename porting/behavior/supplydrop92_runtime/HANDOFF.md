Four uncounted rough proposals in `rough.cpp`, lifted from implementation probes in `porting/generated/native92-impl/` (source hashes in `sources.json`). These are not production definitions or complete parity claims. No build, tests, runtime, or generation was run. The parent owns Ghidra and promotion.

- FindGroundLocationAt (`0x1419142d0`) forwards world, input, +0x790, and the constants 10000/-5000 to `0x141eede00`, then adds +0x834 to returned Z. Helper effects and null behavior remain unresolved; the input type and helper ABI are inferred from the 12-byte wrapper/output and need confirmation.
- GetSupplyDropSpawnData (`0x1419189c0`) delegates to `0x141949a30` for the checked world +0x128 object. Otherwise it gathers class `0x142b90cb0` actors, inspects only the first and predicate `0x142ecc620`, copies +0xb98/+0xb9c if accepted, frees array storage, and defaults to 28000/32000. Array collection and predicate semantics remain unresolved.
- GetSupplyDropSpeedData (`0x141918b00`) delegates to `0x141949b10` for the checked world +0x128 object, otherwise writes 280/500 in order.
- SpawningLootOnDestruction (`0x141922280`) checks input +0x220 for player-state ancestry and calls `0x141a4cf10` with state and address self +0x410. Meaning of that field and helper effects remain unresolved.

The class adapter must preserve the actual depth and ancestor-slot checks and their dereference behavior, including the lack of a null check on the class factory results. The actor array layout and argument types are proposals, not asserted engine declarations. Adapters are explicit unresolved native operations, not fallbacks. Preserve output write order and first-element-only behavior. Security-cookie machinery is omitted.

The bounded extension adds two further uncounted storm proposals from `0x14191c450` and `0x14191c710`. The check routine reads the 12-byte position from root +0x1d0 or the global value, queries the checked mode, clears and zeroes the +0x880 timer handle, and schedules the callback through +0x888 at the float +0x870 with loop false and first delay -1. The delegate allocation, callback-member copy, cloning, weak local and separate destruct/free operations are retained as ordered adapters. The callback representation's last four bytes and local weak object's exact stack layout/hidden call-frame relationship remain unresolved. `local_weak_storage` means an independent local object, not shared global storage; the set-timer adapter must preserve any hidden stack aliasing. Do not promote until delegate construction, weak cleanup, and timer ABI are resolved. Assembly confirms +0x870 is passed as float, correcting Ghidra's `(int)lVar2` rendering.

It rereads registry storage during loops to preserve mutation-sensitive behavior. The world is dereferenced without a null guard on the nonempty-name path.
