# Ammo definition dispatch: partial recovery, do not integrate as closed

`prepare.py` pins the image hash, original-this base constructor/table, slot, wrapper, thunk and weapon entry. The reflected function is `UFortWorldItemDefinition::GetAmmoWorldItemDefinition_BP() const`, flags 0x54020401, returning a `UFortWorldItemDefinition*` (class factory 0x142b56ce0). Exec 0x142b5d0d0 advances bytecode by one when nonnull and calls 0x1420589d0, which dispatches vtable +0x4e8. Native base target 0x140680300 returns null. The native virtual needs its own virtual declaration, with the BP wrapper dispatching to it. Do not infer the virtual's original name from the BP wrapper.

Weapon table 0x1461fea98 selects 0x142669040, which passes `this + 0x978` and true to 0x1424ce740. Generated `UFortWeaponItemDefinition.h` calls this field `TSoftObjectPtr<UFortWorldItemDefinition> AmmoData`. The helper checks an empty path, resolves the weak reference and path, does class checks against UFortWorldItemDefinition, attempts load through 0x141e12f10 with the true flag, then calls 0x141df61e0 and 0x141de9e00 before returning the candidate. This final side effect and the precise loader's contract are not established. A `Get()` or unconditional null is therefore not an equivalent proposal; even a naive `LoadSynchronous()` requires proof of the post-resolution calls and casts. The field layout and whether its generated placement reproduces +0x978 also require checking against the actual UE build layout.

Preliminary reflected parent-map scan found 27 native classes with complete parent chains. Tentative table scans found targets 0x140680300, 0x142669040, and 0x142008520 (Gadget). 0x142008520 is a substantial body that starts by resolving a soft class at gadget +0x8a8 and checks its class; it is not recovered. Two classes, CreativeGadget and PlaysetGrenade, have unsupported constructor patterns in the generic scanner. Constructor-thunk/base-store provenance and slot tables for every derived class must be independently validated before the finite override inventory is considered closed; the naive candidate scanner can select inherited or intermediate tables. In particular the initial scan reports AthenaGadget with the base target, which needs original-this store proof before relying on it. Blueprint event flags of the wrapper are not evidence that a native C++ virtual can be overridden from Blueprint.

Remaining closures: prove every derived constructor's final primary vptr and the two currently unsupported constructors; fully recover Gadget's target and transitive loads; identify and reproduce 0x141e12f10 and the 0x141df61e0/0x141de9e00 post-resolution side effect (including behavior for wrong types, missing assets, and cache mutation); verify exact generated field offset and lifetime. Do not integrate a base-only shortcut into `GetRemainingAmmo`, which dispatches dynamically and can invoke the loading override twice.

## Weapon helper closure and remaining shared tracker dependency

`WeaponAmmoDefinition.proposal.cpp` gives base virtual, Blueprint wrapper, and weapon override with the delay loader matched to the recovered existing startup provider. The soft pointer is consulted through the named generated `AmmoData` field; original offsets do not need to equal the port's semantic layout. The cached `Get()` runs first and a typed failure triggers a separate synchronous path load (the loaded object is not explicitly assigned to the soft pointer). Empty paths return immediately, with no tracker call. All nonempty paths call the tracker even when the result is null. The flag passed by the weapon entry is a timing flag, not permission to load. Original 0x141e12f10 performs `UAssetManager::IsValid() ? GetStreamableManager().LoadSynchronous(Path, false, nullptr) : Path.TryLoad()`, and optionally uses `ShowDelayLoadTimes` and `FScopeLogTime` in seconds. This is independently described and implemented in `porting/frontend/startup_class_providers_runtime/StartupClassProviders.cpp` and its `RECOVERY.md`.

0x141df61e0 returns the static FGCObject named `FFortAssets` (name string at 0x145fdbe10); 0x141de9e00 locks its critical section at +0x1a0. If flag +0x1c8 is set and object is in the set at +0xb0, it does nothing; otherwise it adds the object to the set at +0x100 when the flag is set, and to +0xb0 when clear. It does so even for null. Virtual AddReferencedObjects at 0x141de9e80 visits both sets while locked, and another collection at +0x150 after unlocking. The final cast at 0x1424ce853 tests UObject::StaticClass (class factory 0x142eeab70, whose inline class name is `Object`), so a successful world-definition result is what is tracked.

The proposal intentionally declares `NativeTrackFortAsset` rather than inventing a local permanent GC root: the exact FFortAssets tracking-scope transitions, release and shared lifetime are not recovered, and a private permanent set would change asset lifetimes. Integrating the proposal requires a shared faithful 0x141de9e00 equivalent and the remainder of its lifecycle; this weapon source is therefore not yet self-contained. Gadget override remains separate and pending. `prepare.py` only gates original base and weapon entry, not the loader or shared tracker.
