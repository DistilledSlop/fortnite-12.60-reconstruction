# WorldItem normalized durability: bounded recovery

No normalized override is proposed. The definition virtual at slot 0x4d8 remains unidentified and its dynamic overrides and dependencies are unrecovered. Calling the base implementation directly or substituting 1.0 would lose virtual behavior. The float result also requires preserving SSE semantics; ordinary `FMath::Clamp` is not established as equivalent.

Evidence from image-125 (SHA-256 338c83a2314ccac1040a2c0bb520b893013cc7b58eda58e550da67f5d84de680), constructor and vtable established in the sibling world_item_queries_runtime proof:

* WorldItem vtable 0x14607a630 slot 0x2d0 targets 0x14205a980. It casts `GetItemDefinitionBP()` to UFortWorldItemDefinition and returns 1.0 when cast fails or `bItemHasDurability` is false. Otherwise it saves the definition vtable, calls item slot 0x2c8 (`GetDurability()`), item slot 0x268 (`GetLevel()`), and saved definition slot 0x4d8 with the level in EDX, in that order. It divides the first float by the latter and clamps using `COMISS quotient, +0; JC return +0; MINSS quotient, 1.0`. Thus unordered/NaN quotient returns positive zero, negative quotient returns positive zero, negative zero survives, and positive values over 1 return 1. The saved definition vtable must be respected if there are side effects that change it during the calls.
* Item slot 0x268 is proven `GetLevel` by the existing reflected base exec proof in MANIFEST (0x142959330). WorldItem slot targets 0x14205a560, which adds 0xe0 then tail jumps to 0x141280c10, `mov eax,[rcx+0x28]; ret`. Reflected FFortItemEntry.Level is int32 at 0x28, and WorldItem.ItemEntry is at 0xe0. This supports the standalone override `return ItemEntry.Level;`, subject to the sibling proof's vtable and storage checks.
* WorldItemDefinition GPSC 0x142b5be40 resolves thunk 0x142b59760, constructor 0x142042090 and candidate primary vtable 0x14606f8f8. Slot 0x4d8 targets 0x1407c46d0, an exact `movss xmm0,[0x1459a86f8]; ret`, returning 1.0. This does not identify the virtual or establish derived behavior. Constructor vptr proof and subclass override coverage still need to be checked before promoting that body.

Ghidra finite probes in `porting/generated/callee_probe/world_item_normalized_{1,2}/` (ignored) cover 0x14205a560, 0x142b5be40, 0x1407c46d0, and 0x141280c10. Both probes completed with rollback; project metadata changed. The normalized body is in `world_item_queries_1/0x14205a980.asm`. No canonical files changed and no builds or tests run.

## GetLevel standalone proposal

`python3 -I porting/behavior/world_item_normalized_runtime/prepare_getlevel.py` verified and emitted one helper override and `GetLevel.inc`. The reflected UFortItem base exec is already canonical: flags 0x54020400, `int32 GetLevel() const`, exec 0x142959330 dispatches virtual slot 0x268; base constructor 0x142024010 stores table 0x14606c3f0, whose slot contains 0x140680300 (`xor eax,eax; ret`). The WorldItem override and entry storage are checked above. The script verifies the image hash, exact full exec/thunk/leaf bytes, both original-this constructor vtable stores, reflection and generated types, and absence of conflicting WorldItem bodies or declarations. The base does not need another manifest entry. This is a standalone dependency recovery and does not unblock normalized durability. No build or test was run.
