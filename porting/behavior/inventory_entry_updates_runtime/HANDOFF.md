# Inventory entry update investigation

`NativeNotifyInventoryChanged.inc` and its manifest entry close 0x14201de90 independently. It calls the real `FFastArraySerializer::MarkArrayDirty`, sets reflected `bRequiresLocalUpdate` then `bRequiresSaving` (native writes the adjacent bytes together), and calls virtual `ForceNetUpdate`. The local UE 4.25 implementation resets ItemMap, increments the array replication key skipping -1, and invalidates both cached counts, matching 0x14072a990 and 0x14201de90. No authority guard occurs in this method. Its name is assigned, not recovered.

`EntryDirty.pending.inc` expresses the complete 0x1420397e0 sequencing, but is not in the manifest because its inventory update callee is not closed: check the weak pointer for validity, get it, invoke the update, then set the source entry's bIsDirty even if the inventory update returns early. It must not mark the source first.

0x14201d4c0 remains unclosed. It checks `GetLocalRole() == ROLE_Authority` first. On the replicated-copy branch, `Inventory.MarkItemDirty(Entry)` exactly matches 0x140719c10 and the inlined branch (replication ID/key and array bookkeeping). On the other branch, 0x14202eda0 **generates a new GUID if the existing ItemGuid is all zero**, by calling 0x142c9ff10 (zero-initialized output then CoCreateGuid), stores it in the source entry, and returns it. The caller rejects a still-invalid result. This corrects the abbreviated population handoff: a malformed parse leading to a zero GUID does not directly skip the update; GUID generation is attempted first. The map lookup at AFortInventory +0x340 is within `Inventory` at FFortItemList +0x118, directly after ReplicatedEntries, and has `FGuid` keys and `FFortItemEntry*` values. A missing map entry or null value returns. The destination copy then clears destination bIsDirty, marks destination dirty in Inventory, and calls 0x14201de90. The replicated branch calls 0x14201de90 too. Thus a successful update marks the array dirty twice, once via MarkItemDirty and once in the notification helper.

Do not replace 0x142025400 with `Destination = Source`: it leaves the fast-array base metadata, ParentInventory, bIsReplicatedCopy and bIsDirty untouched, and copies fields individually. Notably it copies a native shared-pointer-like member at `FFortGiftingInfo +0x18` through 0x142025370. The generated FFortGiftingInfo only contains the reflected FString and hero pointer, so its native member's concrete type and ownership must be recovered before the copy can be ported faithfully. The generated FFortItemList also omits the native map; its concrete lifecycle/ownership needs reconstruction and generator support. Copying only reflected fields loses the shared reference, and using struct assignment resets fast-array IDs. These prevent claiming the two caller fragments integrated.

Native bytes are pinned in `native-evidence.json`. Read-only decompiles are in ignored `generated/callee_probe/inventory_entry_updates/` and `inventory_entry_dependencies/`, as well as the earlier `worlditem_population/` and `profile_itemaware/`. Probe transactions rolled back; project metadata changed. No build, tests, integration, or runtime execution were performed.
