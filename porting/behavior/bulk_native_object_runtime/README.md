# Size-backed native object-pointer getter proposals

Run from the repository root with `python3 -I porting/behavior/bulk_native_object_runtime/scan.py`. Capstone must be available in `/tmp/common-input-capstone`. The scanner verifies the SHA-256 of the mapped original image, then writes bodies here and evidence and proposed manifest entries to `/tmp/gameplay-bulk-native-object/` (override with `--output-dir`).

Only complete zero-argument reflected Object getters with matching flags and return ABI qualify. The accepted code is an exact inline qword read and return, or an exact wrapper calling a complete leaf consisting solely of a qword read and return. The return class is resolved from the exact reflection reference through the generator's type resolver. Public, protected and private functions are considered. Both class and parent bounds require unique original registration targets and matching complete registration evidence. Reflected size conflicts abort. The eight-byte interval must lie wholly in the declaring class and avoid reflected properties, canonical native fields and accounted generated-header declarations. Unknown reflected or native field widths reserve through the next known offset or class end; unknown header fields and ambiguous property groups reject the class. Proposed overlapping intervals with incompatible types are rejected. Known weak pointers, handles and other wrappers are occupied storage, including partial overlaps; an unknown-width wrapper is never assumed to be eight bytes.

The raw-pointer declaration follows the proven pointer read and reflected return type. The read alone does not establish the original field's full representation, GC ownership, construction, writing or lifetime behavior; an unreflected larger wrapper cannot be ruled out solely by this read. No initial value is invented. These are source-level proposals, not a claim of binary layout, constructor/writer parity or runtime parity. Integration and validation are required before promotion.

The candidate and field carry `blocked_native_storage_ownership` status. They are evidence only, are not ready for canonical promotion, and receive no canonical body credit until the complete storage representation and ownership are established.
