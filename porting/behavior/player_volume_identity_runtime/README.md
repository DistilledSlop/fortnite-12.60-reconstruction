# Player-to-volume identity lookup

`0x141c7d420` rejects a null or pending-kill player state and invokes `0x141c7d270` on `VolumeActivePlayers`. Its hitch scope is `STAT_Find_Volume`; `QUICK_SCOPE_CYCLE_COUNTER` has the original lightweight scope in the corresponding engine configuration (see `../volume_location_runtime/README.md`). `IsValid` implements the same null/pending-kill check. Neither helper validates a returned volume or rejects a pending-kill pawn.

`0x141c7d270` first checks `APlayerState::UniqueId` validity. If valid, it walks `FFortVolumeActiveUsers::Items` in array order and returns the first matching `FVolumePlayerStateInfo::Volume`, including a null or pending-kill value. An unmatched valid identity returns null without location fallback. Each comparison rechecks both IDs, including the player ID, and two invalid IDs compare equal. UE 4.26 `FUniqueNetIdWrapper::operator==` implements exactly that ordered pair of `IsValid` checks and `FUniqueNetId::operator==`, so the code uses the real `FUniqueNetIdRepl` fields and wrapper equality, without copying IDs. The identity object's virtual `IsValid` is called, not merely the shared pointer's validity.

For an initially invalid identity, the original reads the raw `PawnPrivate` pointer and performs a class cast to `AFortPawn`, resolves the manager from that pawn, and calls the manager's location lookup. `GetPawn()` returns the raw pointer, and `GetActorLocation()` reads the root component location or `FVector::ZeroVector` when root is absent. The captured fallback global at `0x148218630` contains three zero floats. There is no weak-pointer dereference or additional pending-kill check in this path. Resolver and location helper dependencies are `NativeResolveVolumeManager` and `NativeFindVolumeAtLocation` from the integrated prior batch.

The original active-users helper receives the address of the manager's `VolumeActivePlayers` member; the proposed `NativeFindPlayerVolumeInActiveUsers` binds it as a manager member and accesses that field directly. Its caller, names, const qualifiers, and `APlayerState*` signatures are source bindings, not reflected functions. `FFortVolumeActiveUsers::Items` is at +0x108, so the original array lives at manager +0x390; each original entry has stride 0x40, UniquePlayerId wrapper at +0x10 (its shared ID pointer at +0x18) and Volume at +0x38. The player state's ID wrapper begins at +0x248 (shared ID pointer +0x250) and raw pawn is +0x278. Original offsets are evidence, not Linux layout requirements. Reflected generated types expose the fields; engine `PlayerState.h` exposes `GetUniqueId()` and `GetPawn()`.
