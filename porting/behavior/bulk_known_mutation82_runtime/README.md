# Known-field no-argument mutations

`python3 porting/behavior/bulk_known_mutation82_runtime/scan.py` reuses the existing complete no-argument mutation instruction families and reflection inventory, and resolves writes only to already-declared reflected or canonical native scalar fields. It does not create storage. It excludes canonical functions and the batch82 additions, checks package, exact class/parent declaration, flags, generated field type, inheritance access and name shadowing, exact offset and width, and for packed bools exact single-bit mask. Unsupported assignments, ambiguous matches, and declarations absent from generated headers are rejected. At most 20 proposals are written here, with complete instruction bytes and SHA-256 pins in report.json; review each before integration. Current inventory scan found zero remaining instruction-family matches after existing bodies and the three batch82 proposals were excluded.

The original runtime image is read through mmap, avoiding a full image hash. Its expected SHA-256 is recorded in report.json but is **not reverified by this scan**; users must independently verify identity when the evidence image changes. The scan uses the existing image previously pinned by the mutation scanner. It does not establish constructor, writer, lifetime, runtime, or build parity. It only recognizes the two inline FFrame-advance sequences and one constant mutation followed directly by RET; wrappers, authority-guarded multi-field bodies, other instruction shapes, and fields with unsupported declarations remain outside its coverage. No generation, build or runtime tests were run.
