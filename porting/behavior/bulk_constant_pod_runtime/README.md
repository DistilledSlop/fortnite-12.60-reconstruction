# Zero POD return scanner

`python3 porting/behavior/bulk_constant_pod_runtime/prepare.py` writes finite source proposals and full instruction evidence under `/tmp/gameplay-bulk-constant-pod/`; it does not promote them. The image SHA-256 is pinned in the scanner. It matches only complete zero-argument FFrame wrappers with exact inline zeroing, or a direct call to a complete zeroing sret leaf followed by complete same-buffer output copying. Every returned byte must be covered; all other instructions, branches, indirect calls, incomplete copies, and unknown values are rejected. Explicit component constructors avoid uninitialized defaults. The struct table requires matching CoreUObject package, name, C++ type, and exact size. Existing canonical/maintained bodies, non-selected or ambiguous classes, problematic function flags, and incompatible generated declarations are excluded.

2026-11-03: 23,758 inventory records, 220 POD returns considered, **zero proposals**; 63 eligible bodies did not match the complete pattern. Evidence: `/tmp/gameplay-bulk-constant-pod/report.json` (image SHA and rejection counts). No Native promotion, builds, or runtime tests. The zero count is a bounded finding, not evidence that every unmatched getter lacks a constant return; nonzero values and other ABI forms are deliberately outside this matcher.
