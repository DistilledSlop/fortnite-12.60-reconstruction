# Building dispatch recovery

`ABuildingActor_dispatch.lift.cpp` records the entire observed native foliage dispatcher and the initialization exec's virtual dispatch. This is evidence, not integration-ready source or a complete recovery of initialization. No manifest entry is proposed. Slot names and the base implementations remain unresolved; a fresh vptr lookup is required for each call in the foliage body.

Evidence: `porting/generated/native89-broad/0x142737640.{c,asm,json}`, `0x142737e30.{c,asm,json}`, and `porting/generated/native90-building/0x141bc24b0.{c,asm,json}`. The reflection function records identify the parameters. The wrapper reads two 8-byte values then one 32-bit boolean and passes them in that order; the reflection records list properties in reverse order. The initialization argument pointer types are inferred, not established by the wrapper. No logging or other side effects appear in either wrapper or the foliage dispatcher itself; virtual callees may have side effects.

Resolve the `ABuildingActor` vtable bindings at +0x810, +0x980, and +0x988 and inspect their implementations before translating to named calls or promoting either body. A leaf native dispatcher could eventually be promoted once those virtual method names are established, preserving dispatch and ordering.

The expanded lift includes the primary vtable base bodies from `porting/generated/native90-targets/` at 0x141baf090, 0x141bc2c30, and 0x141bc8570. Actor +0x3e6 bit 0x80 is `bDestroyFoliageWhenPlaced` per `reflection/bool_bits.json`; +0x538 is `OverridePrimitivesToExcludeFoliage` per reflection. Component +0x84 bit 1 and the precise slot names remain unresolved. `FBox(ForceInit)` captures validity but native initializes min/max using a global vector; their exact value is irrelevant until a valid box is supplied, provided the unresolved call does not inspect the initial out value. Initialization +0x880 gets six ABI arguments in both mode branches; asm explicitly supplies the controller-derived uint16, owner, null, and false before the branch, correcting the decompiler's omission in the mode 1 path. Slot +0x888 is called afterward with the same mode.

The five dependency probes are in `porting/generated/native90-deps/`. 0x1423881c0 reads controller +0x220, class-checks the object and returns its uint16 at +0x336, default 0xffff. 0x141f88460 resolves a world context, checks the object at context +0x130 against a class and returns its +0x3d0 member. 0x141f967e0 validates its box and appends an eight-byte actor-derived key and 28-byte box to the manager array at +0x218; 0x141f9f2c0 converts the actor to the same key and forwards it to 0x143af03b0. Both re-check 0x143f7a920 on the manager. That helper takes a receiver, examines its world and name, and returns a value derived from a selected world-associated object; value 1 suppresses both operations. Its likely net-mode meaning is not yet proven. The caller decompilation had omitted the receiver argument, now corrected in the lift. Helper operations remain labeled rather than falsely named; these additions are evidence sketches, not source promotion.
