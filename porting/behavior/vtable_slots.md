# Vtable slot name map (engine and game classes of the blocked bodies)

Generated by `porting/behavior/build_vtable_slots.py` (`python3 -I porting/behavior/build_vtable_slots.py`, about 5 s).
Data: `porting/behavior/vtable_slots.json`. Lookup: `python3 -I porting/behavior/vtable_lookup.py <class> <hexoffset>`.
Inputs are read-only: the UE 4.25 engine headers, the runtime dump image (`porting/generated/dump/`), `native_class_index.json`
(GetPrivateStaticClass addresses) and `class_parent_map.json` (parent chains). Nothing under `porting/native/` is touched.

## Method

1. **Model (header order, MSVC rule).** Each engine header is parsed with the Shipping macro set (`MACROS`: WITH_EDITOR 0,
   WITH_EDITORONLY_DATA 0, UE_BUILD_SHIPPING 1, WITH_ENGINE 1, ...). A class table starts as a copy of its primary base table;
   a declaration whose signature matches an inherited entry replaces it (override keeps the slot), any other one is appended.
   A virtual destructor is one slot (the scalar deleting destructor), and every class with a virtual base destructor has its own
   slot 0. Macro-declared virtuals (`HIDE_ACTOR_TRANSFORM_FUNCTIONS()` in Actor.h) are expanded in the classes that invoke them.
   Secondary bases (`INavAgentInterface`, `IInterface_AssetUserData`) are not in the primary table.
2. **Dump tables.** `GetPrivateStaticClass` (native_class_index) -> `InternalConstructor` thunk (`if (*this) Ctor(*this, this)`)
   -> constructor. The primary vptr is the `lea reg,[vtable]; mov [base],reg` store with no displacement. Where several stores
   qualify (inlined base constructors), the one that agrees most with the ancestor table is chosen. The table scan stops at the
   next known table start.
3. **Validation (per slot, against the dump).**
   - *stub*: an inline empty / `return true` / `return false` body must be the folded stub the linker kept at that slot
     (`0x1406801c0`, `0x1406801d0`, `0x1406801e0`). This pins the absolute index.
   - *identity*: an inherited slot must hold the same entry as its owner class table at that index.
   - *override*: a slot the class declares must differ from its parent entry (weak).
   - *anchors*: `UObject` 66 (ProcessEvent), 42 (GetWorld), and `AFortPlayerStateAthena` 238 (GetPlayerTeam, body check).
4. **Confidence.** `validated` = the dump check passed (stub or identity). HIGH = validated, and the owner table is aligned
   (at least 90% of at least 5 of its inline stubs match). MEDIUM = not validated, but the owner table is aligned. LOW = the
   owner table is not aligned, or the dump disagrees with the model.
5. **Game classes.** Their table starts with the nearest engine ancestor table (indices below the engine length are exact).
   Game-declared virtuals sit above that length (`game_part_from`) and have no names here: the game headers are not
   available, and the generated headers declare almost no virtuals.

## Limits

- The name is the 4.25 declaration. The shipped engine and the Fortnite fork diverge (APlayerController 203..232, UHT-generated
  `ValidateGeneratedRepEnums`, `PostDuplicate(bool)`); those slots are reported as divergences, not as names.
- Game virtuals (index >= `game_part_from`) are not named. Only RPC thunk call sites (`decompilation_notes.md`, Eighth/Tenth pass) name
  some of them, from inference, not from this map.
- AFortPlayerPawnAthena has no constructor vptr found (its constructor is a short tail jump that the scan does not follow).
- Own virtuals of a class are confirmed only by stubs that class declares (`region_alignment`). APlayerCameraManager
  declares none, so its own slots are LOW: the dump body at slot 224 returns a 12-byte value, the model says void,
  and slot 219 (GetCameraRotation in the model) is a bool-returning body. The shipped table differs from the 4.25 model here.
- Some constructors store the vptr inside the InternalConstructor thunk after the call (UPawnMovementComponent); those are
  read from the thunk when the constructor only reaches an ancestor store.
- Secondary vtables (interfaces) are not modelled.
