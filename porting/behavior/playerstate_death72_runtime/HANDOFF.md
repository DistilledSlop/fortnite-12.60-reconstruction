# OnRep_DeathInfo rough lift

This is a behavioral research lift, not canonical C++ or a verified ABI. The entire 1,747-line improved decompilation was read. The connected lift covers the entry, default death-info selection, distance handling, local kill delegate, both notification paths and fallback formatting, game-state dispatch, controller/player callbacks, subsystem effects, marker selection and emission, and exit cleanup. Coverage is **partial at engine-operation granularity**: the adapters intentionally encapsulate substantial engine internals, particularly formatting, reference counting and marker payload construction. No adapter is implemented and there are no fabricated engine defaults. It must not be linked as implementation until those contracts are recovered.

## Marker refinement

`marker.rough.cpp` and `marker.rough.hpp` expand the append and optional event path and are called directly from `rough.cpp` through `Engine::marker_engine()`. The marker record writes the observed complete six words in order after increment/grow. The upper 48 bits of the last record word are an explicit adapter to prior stack state: the source only overwrites its low two bytes at that point; assuming zero would invent behavior. The expanded payload uses stack-relative offsets and intentionally leaves unwritten bytes unspecified. All constants assigned in the source, overwrites, helper calls, FText word swap, temporary destruction, registry lookup, send and two final cleanup calls are represented in source order. The source appears to cast DAT_148218638 to float at initialization; its actual type/representation needs confirmation.

`MarkerEngine` declares individual engine access/call adapters rather than implementing ABI. In particular, raw record write must write the 0x20 bytes without normalizing the retained high bytes; the text swap and `destroy_text_140683490` must reproduce the source's reference ownership; and helper initialization/destruction must know the true nested object sizes. The scratch storage sizes are based on observed stack extents and are not verified native layouts. The adapter for `marker_array_grow_14069e9b0` must operate on the array at game state +0x2768 and preserve the already incremented count. A null game state is intentionally not checked in this branch, matching the decompilation. No tests or compiler were run.
