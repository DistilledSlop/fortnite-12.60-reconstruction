# Athena infinite-ammo iterator: source proposal

`Proposal.cpp.in` reconstructs the complete loop and iterator control flow, with four native dispatch seams and the existing volume lookup called out explicitly. It is an integration proposal, not a drop-in build: the generated interfaces have no native methods yet, and the descriptive binding names and exact declaration types must be installed consistently on the relevant native classes. Do not replace these seams with no-ops or a global mutator array. In particular, the fallback lookup is the existing world/volume-selection operation, not simply the game state. No build, test, or runtime execution was performed.

The applicable capture is `/mnt/vibrato/fortnite-evidence/original-late-capture-1/image-125.runtime.bin`, base `0x140000000`, SHA-256 `338c83a2314ccac1040a2c0bb520b893013cc7b58eda58e550da67f5d84de680`. Decompilation and disassembly are in `porting/generated/callee_probe/infinite_ammo_rule/`.

## Required native binding contracts

* `IFortMutatorContext` virtual `+0x10`: append owner objects to the supplied array. Called only when the context implements the interface. Preserve the implementation's ordering, duplicates, and side effects. Otherwise `0x141c74820` locates the Athena game state's volume manager, and `0x141c7c5c0` selects a volume for the context by overlap/containment and priority, including its special actor interface fallback and recursion guard. Add the resulting non-null volume uniquely. These existing native operations must be ported or bound, not reduced to a getter.
* `IFortMutatorOwner` virtual `+0x20`: append gameplay mutator candidates to the passed array, receiving the weak context resolved at call time. Otherwise call the owner's virtual `+0x610` with `UFortMutatorListComponent::StaticClass()` and append its `Mutators` array at `+0xe0`. The owner source's static type and original symbol names are not recovered; UObject pointers in the proposal represent object identity, not permission to call component lookup on arbitrary UObjects.
* Mutator virtual `+0x6b8`: set/clear context. Preserve dispatch for every invocation, including apparently redundant null calls and when the weak context resolves null. Base `AFortAthenaMutator` implementation is empty (`0x1406801c0`), but derived overrides may have effects.
* Athena mutator virtual `+0x9b8`: `(bool& output, weapon definition*) -> uint8`. Base returns 0 without touching output (`0x1406801e0`); preserve derived dispatch. The `AFortAthenaMutator_InfiniteAmmo` override `0x141aa75e0` writes `bInfiniteAmmo` and returns 2. Its reflected bool setter is a byte write at `+0x270` (`bool_bits.json`); the override reads that byte. The enum and method names remain unknown; 2 is the observed stop value, not an invented enum declaration.

Class identity evidence for the base slots: `AFortAthenaMutator` StaticClass `0x1427dc340` registers constructor thunk `0x1427df000`, which jumps to `0x141a689a0`; its store at `0x141a689bf` installs primary table `0x145e44758`. Table entries at `+0x6b8` and `+0x9b8` point to the base functions above. InfiniteAmmo class/table provenance is recorded in the sibling `infinite_ammo_rule_runtime/HANDOFF.md`.

The active predicate `0x1420e5530` tests low bits at `+0x248` and `+0x220`. Reflected setter data in `porting/generated/reflection/bool_bits.json` maps these to `bMutatorActiveInternal` and `bMutatorActive`, respectively. Either one suffices. The component list is `TArray<AFortGameplayMutator*>`; candidates are cast to `AFortAthenaMutator`, and invalid or inactive entries are skipped.

Iterator construction and traversal match `0x1419b90a0`, `0x1419f3bf0`, `0x1419f3d90`, and destruction `0x1419bb7e0`. An important detail is that crossing from a nonempty owner to another nonempty owner can clear the old current twice: the out-of-range candidate selection clears it, then selecting the next owner's first candidate clears it again before overwriting the pointer. Empty owners between them do not overwrite it. Exhaustion sets current null. Destruction clears a still-current mutator, including on control value 2. Candidates are snapshotted separately per owner; provider order and duplicates are retained. The accumulator uses bitwise OR after every callback, so true does not short-circuit later callbacks.

The proposal deliberately leaves unresolved native method declarations, provider implementations, the full volume lookup and derived overrides as integration dependencies. Its virtual call boundaries preserve these behaviors, but substituting placeholders would not be a faithful implementation. For original caller casts and the independent controller flag, see the sibling handoff.

## Integration and gate

`manifest-entries.json` and the three `.inc` bodies propose the independently closed base context setter, base query, and InfiniteAmmo override. `prepare.py` pins the two constructor thunks, constructor table stores, both vtable slots, predicate and body bytes, and reflected field offsets against the capture. Its read-only evidence gate passed. Original class registration and InfiniteAmmo constructor provenance are described above and in the sibling handoff. The proposal requires adding a forward declaration for `UFortWeaponItemDefinition` to the generated Athena mutator header when emitting the assigned query signature. The derived method must remain an override of the same C++ virtual; generator method deduplication must not suppress its declaration or body. The context setter is also virtual. Other derived overrides remain independent follow-up ports: leaving them as inherited base implementations changes behavior for those classes and does not close the full rule.

The iterator also requires generated native interface declarations for `IFortMutatorContext` (owner-array appender) and `IFortMutatorOwner` (candidate-array appender with context), and declarations for the mutator methods above. `AFortGameModeAthena` is a proven native `IFortMutatorOwner` implementer (see `athena_mode_reconstruction_runtime/migration-contract.json`); its implementation and other dynamic owner/context implementers are not established here. Their native implementations must be preserved or recovered before integration can claim a complete executable port. The generated `UFortMutatorListComponent::Mutators` is already available. The existing generator currently emits empty interfaces, so add native interface declarations through its interface-generation path, plus generated class inheritance/overrides for every proven implementer; simply emitting the three method entries cannot create those dispatch implementations. Likewise bind the owner `+0x610` component lookup and volume-manager operation with their actual existing actor types. Exact provider interface argument static types and method names remain unproven; the proposal's `UObject*` is intentionally an opaque identity contract, not a recovered signature.
