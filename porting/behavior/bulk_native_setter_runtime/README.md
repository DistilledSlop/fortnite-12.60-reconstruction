# Native scalar setter storage proposals

Run `python3 -I porting/behavior/bulk_native_setter_runtime/prepare.py` from the repository root. It requires Capstone in `/tmp/common-input-capstone`, the pinned runtime image used by the existing setter scanners, and the existing bool, int and float setter scanner patterns. The image SHA-256 is verified. The script writes source proposals in this directory and `/tmp/gameplay-bulk-native-setter/{manifest-entries,report}.json`; it does not modify the canonical manifest or generated headers.

The scan requires a complete exact FFrame parameter extraction with consistent locals and branch targets, plus either a complete pure writer or the matched inline float store. It applies the scalar storage scanner's unique class and generated parent checks, agreeing positive class and parent Bool `size_of_outer` evidence, class-local bounds, and conservative reflected and canonical native field occupancy. Unknown property widths reserve through the next known offset or class end. Overlapping proposed intervals with different type or width are all rejected. Existing occupied fields are not reused or overwritten; missing initialization and other writers are not inferred.

The current scan proposes two setters and two fields: `AFortGameModePvE.SetIdleDetectionPenaltyTime` and `UFortBaseButton.SetBangVisibility`. The 41 other matched stores are blocked by absent size/header evidence, occupied storage, or a name collision, as recorded in the report. These are source-level proposals; generated declaration order does not establish original binary layout, and initialization, other writes and class behavior remain unported. No build or runtime test was performed.
