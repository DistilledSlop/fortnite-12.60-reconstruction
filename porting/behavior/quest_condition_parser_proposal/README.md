# Quest condition parser proposal (blocked)

`parser.draft` is a partial translation of native `0x14240d370`; it is not a generated input, completed body, or verified implementation. The missing quest-specific token definitions and grammar are required before it can parse any condition faithfully. No manifest entry is supplied.

The function allocates a single shared object with a 16-byte reference controller followed by a 48-byte payload: a `TArray` at payload +0x00, input `FString` at +0x10 and error `FString` at +0x20. It copies the source into the payload before parsing, which preserves the source storage backing token contexts. Calls `0x142c9c750` and `0x142c8c770` match UE 4.25 `ExpressionParser::Lex` and its token-array `Compile` overload, respectively: the former consumes a UTF-16 string through token definitions and returns tokens or error; the latter compiles the consumed tokens with the grammar. The successful compiled token array is moved into the payload (native element stride 0x68; lexical tokens have stride 0x58). On either failure, native converts the error text to a string, stores it, logs the input and error at error severity if enabled, and still returns the shared payload with its input and empty compiled-token array. Caller must not treat failure as a null pointer. Regular, non-atomic refcount operations in the shared cache path indicate non-thread-safe shared ownership; retain this as an implementation inference until its full object constructors/destructor are recovered.

Evidence: `porting/generated/quest-row-post-probe3/0x14240d370.{c,asm,json}`, `porting/generated/quest-parser-probe/0x142c9c750.c` and `0x142c8c770.c`; corresponding UE source is `Engine/Source/Runtime/Core/Private/Misc/ExpressionParser.cpp`. `0x142c40540` retrieves the error's text; `0x140683960` copies the string. Probe captures are ignored local artifacts; probe transactions were rolled back, although Ghidra reported metadata changes on project open.

Unresolved: construction, lifetime and destruction of the quest parser singleton at `0x14815f750`; token consumers at singleton +0x50; grammar at +0x68; all token node types and operator precedence/associativity; exact log category; evaluation and tag extraction; and compiler/runtime compatibility of the proposed C++ object layout and move operations. Further recovery should identify singleton initialization and its registration callees before implementing parser behavior. The separate row post-serialization closure remains blocked. No build or runtime tests were run.
