# Volume location selection

`0x141c7cde0` scans `AFortVolumeManager::VolumeObjects` in order, ignoring null pointers and volumes that do not contain the location. The first match wins initially. A later match replaces it only when its bounds box X extent compares below the current X extent **and** its Y extent compares below the current Y extent. Z extent and volume priority are not consulted. It does not reject pending-kill volumes. The first comparison's x86 `COMISS`/`JNC` admits unordered X values, whereas the second `COMISS`/`CMOVA` requires an ordered Y comparison; the candidate source retains this distinction.

Containment `0x141c82210` reads `AFortVolume::BoundsShape` (original +0x560): Box (1) checks all three inclusive axis-aligned intervals, and Sphere (0) checks the squared distance to origin against `(SphereRadius + 0.0001f)^2`; other shape bytes return false. Box lower bounds use `COMISS`/`JC`, so unordered values fail there; upper bounds use `COMISS`/`JA`. Sphere arithmetic adds Y squared to X squared, then Z squared. Bounds helper `0x141c75610` copies the 28-byte `FBoxSphereBounds` from `BoundsComponent->Bounds` each time it is called. Reflection identifies `VolumeObjects` at +0x278, `BoundsComponent` at +0x2a0, and `BoundsShape` at +0x560. `UPawnOverlapComponent` derives from `UStaticMeshComponent`, and local UE 4.26 `USceneComponent` exposes `Bounds`. The original scene-component field at +0x100 has the same origin, box-extent, sphere-radius layout. These offsets are evidence, not Linux layout requirements.

The proposed manifest binds three methods: `NativeGetLocationBounds`, `NativeContainsLocation`, and `NativeFindVolumeAtLocation`. The original bounds helper returns an ABI output buffer; the assigned void output-reference binding copies the bounds when present and otherwise leaves the supplied object unchanged, after logging at Error through `LogFort`. The log category is established by `../aircraft_lookup_evidence.md` (the same original global `0x1481348e0`); `GetName()` supplies the original object's FName text. Callers declare `FBoxSphereBounds` locals with the UE 4.26 default constructor, which leaves their fields uninitialized. The selection reuses the two local buffers in the same sequence as the original. If a component is absent, later reads of those untouched fields are indeterminate in C++; stack contents and compiler behavior cannot be guaranteed to match the original machine code. This is preserved as the original source-level contract rather than replaced by invented bounds or a null rejection.
