# Integration review

The eight proposed manifest entries are not ready to integrate into the current generator.

- `gen_native_classes.py` renders UInterface headers separately and excludes interfaces from the class models that receive manifest snippets (around lines 4153 and 4370). The four interface `exec` entries are therefore rejected as an interface class not generated for splicing. Their snippets contain comments only and would not implement dispatch even if attached as ordinary bodies.
- The four actor entries use `kind: impl` with ordinary names. `attach_snippets` accepts `impl` only for RPC names ending in `_Implementation` (around line 3181), so these entries are rejected. The generated actor currently has no `IFortClientAnnouncement_TutorialInterface` base or method declarations. A dedicated interface policy must establish the correct inheritance, declarations, and dispatch before these implementations can be wired in.
- The proposed context lookup is not supported by the current source model: `UFortTutorialContext` derives from `UBlueprintContextBase`, a `USubsystem` declared `Within=LocalPlayer`, rather than `UWorldSubsystem`; its generated declaration has no `UpdateTutorialAnnouncement` method. `UWorld::GetSubsystem<UFortTutorialContext>()` and the proposed call therefore do not express a usable existing API. The raw wrapper capture establishes parameter unmarshalling and an indirect slot call, not the context lookup used in the actor body. Capture and verify the concrete bodies and their context/notification path before translating that path.
- The actor belongs to FortniteGame and the context belongs to FortniteUI. FortniteUI already depends on FortniteGame in its Build.cs; adding a direct reverse dependency would create a module cycle. Any cross-module notification needs an appropriate existing or newly designed bridge, supported by the binary evidence.
- The evidence's claimed offsets within `TutorialData` are eight bytes larger than the reflection offsets in generated structs: Title `0x88`, Detail `0xa0`, Name `0xf0`, System `0x108`. The stated actor offsets may still be correct if the struct begins at actor offset `0x290`; verify the base and call-site pointer adjustment before using the evidence offsets.

This review used source and the saved wrapper capture; it did not independently recapture the four concrete bodies, run a build, or run tests.
