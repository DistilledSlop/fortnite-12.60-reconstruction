# Inventory GUID index rebuild

The actual writer is the opening phase of AFortInventory reconciliation `0x14201f180`, not a separate map-only function. It calls `0x142005440` with zero on inventory +0x340 (map Empty(0)), then visits every ReplicatedEntries element in increasing order, calls `0x14202eda0` to acquire/generate its GUID, and inserts the GUID and address of the array element via `0x141ff6ae0`. The insertion helper's `0x142004ee0` replaces the value on duplicate key: the last entry wins. There is no validity guard on the generated GUID. Empty(0), rather than Reset or reserving array length, preserves native allocation behavior.

Crucial ordering: immediately after population it iterates ItemInstances (+0x390); a null slot calls `0x14201a570` to remove one ReplicatedEntries (+0x330) element at that index, decrements the loop index and retries. This call can move or shrink that array after its addresses were indexed. Do not add an invented repair/rebuild or assume the map remains valid. The exact null behavior is odd: the native code removes from ReplicatedEntries, not ItemInstances; do not silently correct it. Next, it empties and repopulates another GUID map at +0x3a0 from ItemInstances, then removes unmatched/invalid instances with RemoveAtSwap-like behavior, removes their keys from the second map and invokes `0x142066bc0` on the removed object. This leaf is closed as `NativeDetachFromInventory` in the manifest: owner cleared, entry weak parent and replicated flag cleared, pending persistent delete set in that order.

Remaining reconciliation is substantial and **not ported**. It iterates entries, uses virtual inventory interface +0x218 slot +0x18 to find real instances, reuses matching pending objects from +0x410 or creates via `0x14205f090`, appends to ItemInstances and its +0x3a0 map, and tracks new/removed/modified items in three temporary arrays ultimately appended to +0x420/+0x430/+0x440. Existing instances receive a field-by-field copy when their replicated entries are dirty, including count-change virtual callback; it processes real-item dirty state too. It rebuilds +0x400 shared-owned grouping objects using item virtuals +0x448/+0x450, optionally sorts instances on non-authority, clears +0x410, then appends event arrays. The +0x3a0 map, +0x400 grouping type/ownership, interface and several virtual bindings are not yet emitted/closed; avoid partial function credit. Next function to close is `0x14201f180` itself after reconstructing these members and `0x14205f090` creation (class-selection virtual +0x518 and initialization virtual +0x4c8); inspect original decompile and connected virtuals. Caller `0x1420159a0` appends a replicated entry, copies the item entry, sets replicated parent, marks dirty, adds original item to +0x410, then immediately invokes reconciliation. Other caller `0x1420147f0` invokes reconciliation before inventory-owner notifications. Neither caller is claimed complete.
