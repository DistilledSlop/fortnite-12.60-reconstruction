# Embedded reflected array counts

`prepare.py` scans the native reflection inventory against the SHA-256-pinned original runtime image. It accepts only complete, parameterless int32 exec wrappers with either an inline load or a direct call to a complete `mov eax, [rcx+offset]; ret` leaf. Virtual dispatch and other control flow are excluded. It resolves exactly one reflected class struct property and one reflected array at the loaded offset minus 8, including an original named inner property, and requires matching generated declarations and module identities. It rejects multiple reflected paths to the same count word and existing definitions or declarations. Element types are deliberately limited to recognized primitive types and uniquely resolved reflected structs; this is a finite conservative scan, not a claim that all array getters were recovered.

The local engine source `Engine/Source/Runtime/Core/Public/Containers/Array.h` defines `Num()` as returning `ArrayNum` and lays out allocator storage followed by `ArrayNum` and `ArrayMax`. `ContainerAllocationPolicies.h` defines the default allocator as the 32-bit-sized default allocator; its heap storage is a pointer. On the original x64 target this places the int32 count at array offset 8. The generated declarations here use default `TArray<T>`, not alternate allocators.

The proposals are `AFortPlayerStateZone::GetSpectatorCount`, which reads `Spectators.SpectatorArray.Num()` at class offset `0x9e8 + 0x108 + 8 = 0xaf8`, and `UFortReplaySequenceComponent::GetNumberOfShotsInSequence`, which reads `SequenceShots.Shots.Num()` at `0xb8 + 0 + 8 = 0xc0`. Original complete wrappers, leaf instructions, reflection offsets, and proposed manifest entries are recorded by the scanner under `/tmp/gameplay-bulk-struct-array-count/`. The `.inc` files are proposals; canonical manifest and generated declarations remain owned by the integration workflow.
