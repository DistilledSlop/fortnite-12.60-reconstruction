# Item dispatch contracts

Four proposed helper bodies restore the connected native virtual operations with assigned names, not recovered original symbol names. `NativeGetItemType` and `NativeGetItemGuid` remain virtual at their declaring base; WorldItem overrides the GUID operation. Source-level const qualification and original symbol spelling are not independently proven; the GUID method is non-const because the WorldItem implementation mutates its entry. These are C++ dispatch contracts, not claims that generated source reproduces original vtable byte layout. The item type is the reflected `EFortItemType` (`Max_None` = 112), and `FGuid` is the 16-byte return value indicated by the hidden return pointer ABI.

* Item slot +0x318, 0x1420337a0, invokes item virtual +0x3e8 (`GetItemDefinitionBP`) once. It returns `Max_None` when null; otherwise it tail-dispatches definition slot +0x298. Base item and WorldItem, CreativeWorldItem, and PlaysetWorldItem primary tables all select this target. The definition call stays virtual.
* ItemDefinition slot +0x298, 0x14202f190, returns the byte at +0x51, reflected `ItemType`. Both ItemDefinition and WorldItemDefinition primary tables select this implementation. Derived definition overrides have not been inventoried or closed and remain dispatchable.
* Item slot +0x468, 0x140693ec0, zeros both qwords of the GUID return storage. WorldItem and its two known native derived tables select 0x14205a3d0, which passes `ItemEntry` at +0xe0 and caller return storage to 0x14202eda0, the already integrated `NativeGetOrCreateEntryGuid`. That helper may write a generated GUID. Other derived item overrides have not been inventoried or closed.

The inventory helper 0x142015840 remains unclosed. The AFortInventory GetPrivateStaticClass 0x142952aa0 resolves constructor 0x141ff9970, whose candidate primary table is 0x14605b6b8; its slot +0x630 is 0x1420159a0. Its original body appends and initializes an item entry, calls multiple helpers, and appends an item pointer. This target is not a stub, and derived inventory dispatch has not been closed. Neither substituting the base target nor omitting this call is justified. Its initial code window is pinned for follow-up.
