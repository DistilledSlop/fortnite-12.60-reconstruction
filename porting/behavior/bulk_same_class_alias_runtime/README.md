# Same-class direct wrapper alias inventory

`python3 porting/behavior/bulk_same_class_alias_runtime/scan.py` checks the SHA-256 pinned original runtime image and writes `/tmp/gameplay-bulk-same-class-alias/{report,manifest-entries}.json`. The current run found 1,704 eligible direct wrappers, zero collisions with a canonical complete function in the same class, and zero proposals.

The scan is intentionally narrow. It recognizes the complete parameterless scalar/object return wrapper consisting of the exact FFrame advance, a direct native call, the matching return store, and epilogue. It requires an unambiguous selected FortniteGame/FortniteUI class, ordinary native instance flags, the same class, exact function flags, the entire identical reflected return-property record, and the same direct call target. Only Bool, Byte, Int, Float, Object, and Class returns are included. Existing ported function and implementation pairs are excluded from the unknown side. Event, RPC, static, virtual dispatch, void, and other wrapper forms are not recovered here.

A collision is an audit lead, not a proposal: the scan does not establish that the canonical include is parameter-free and resolves its dependencies, that generated or maintained declarations and definitions are absent, or that cloning preserves native body versus virtual dispatch semantics. Therefore it always emits an empty proposal manifest. It does not infer aliases from names or partial machine-code matches, and the zero result is limited to the recognized wrapper family and current canonical manifest.
