# Action binding creation entry: bounded original-image contract

Static analysis of `/mnt/vibrato/fortnite-evidence/original-late-capture-1/image-125.runtime.bin`, base `0x140000000`, SHA256 `338c83a2314ccac1040a2c0bb520b893013cc7b58eda58e550da67f5d84de680`. Run `python3 /mnt/vibrato/fortnite-work/action-binding-create-entry-1/replay.py`; it hashes the image and full entry/caller windows, validates all five rejection strings and pdata coverage, then runs five supporting proofs. This is not runtime verification. PE exception directory has one entry `0x800e60..0x8014ff`, unwind `0x736284c`, flags zero: there are no chained unwind fragments for this helper. The entire function through its epilogue was traced, not only the initial basic block. Supporting storage proof covers its own complete chained-unwind functions.

## Contract and order

Windows x64 `0x140800e60(out int32* RCX, widget* RDX, descriptor* R8)` returns the **same out pointer** in RAX, and writes the ID or -1. Both output and descriptor must be valid; widget is consumed by logging, weak capture and (legacy path) virtual dispatch. Do not infer that a null widget is supported just because the direct entry lacks an explicit test.

1. `0x1407c17b0(descriptor, &name)` derives the name. Both FName words zero reject as no action. With no table and no row name the tag is used; a row name without table yields None; present table produces `Legacy_<Table UObject name>_<RowName>`, irrespective of tag. See `action-binding-record-constructor-1/HANDOFF.md` for details.
2. Reject if descriptor +48's delegate allocation/count word is zero, descriptor +40's instance pointer is null, or that instance's virtual +28 returns false. This is the required click delegate's validity check, not a callback invocation. Click signature is `void()`; descriptor +50 is optional progress `void(float)` and is copied into the record multicast if bound. See `action-binding-delegate-contract-1/HANDOFF.md`. Do not conflate progress with the required handler or invoke either during creation.
3. If descriptor tag +0 is non-None, call `0x140811ec0`, obtain class +130 CDO (initializing with class virtual +390 if null), and `0x1407bd6e0(CDO, tag)`; null rejects. This is `GetDefault<UCommonUIInputSettings>()` and the InputActions collection, not ActionOverrides. Validation occurs even if a legacy table is also supplied.
4. If legacy row handle +8 is nonempty (nonnull table OR non-None row name), call `0x14078c640(&row, TEXT(""))`; null rejects. Empty row skips this validation. Thus tag and row are independently validated when both are present. Row lookup itself may emit UE DataTable diagnostics before entry-level rejection; exact behavior and type checks are in `action-binding-row-provider-1/HANDOFF.md`.
5. Iterate every live entry in global registry `0x14782ede0`; compare both derived-name FName words with map element +8, descriptor +1c event with element +10, and `0x142ee5dd0(element+18)` resolved weak widget with incoming widget. First match rejects; never reuse/update the matching ID. Other fields, delegates and row do not distinguish duplicates. The name helper is called again per entry.
6. Construct temporary record at `0x140795760(&record, widget, descriptor)`. This copies owned values/delegates, allocates its ID from a process-global postincrementing 32-bit counter into record +58, and constructs display/key data. Full field mapping, branch ordering and threshold behavior are in `action-binding-record-constructor-1/HANDOFF.md`; selected legacy gamepad requires the real player/router/input-subsystem chain described in `action-binding-gamepad-provider-1/HANDOFF.md`. No fallback exists for failed providers or invalid index. In particular constructor selects tag branch solely by non-None tag; otherwise it dereferences the resolved legacy row. The entry's empty-row skip is not a guarantee that this downstream precondition is met under every malformed descriptor.
7. `0x14078b3e0(global, ..., {&record.ID, &record}, false)` copies the record into its unique-key map; the key pointer is `&record + 0x58`, **the exact ID allocated in step 6**. A duplicate integer key replaces an existing map value, per storage proof; duplicate logical-action scan does not prevent counter-wrap key collision. After insertion the caller reads that same temporary ID and writes it to `*out`, then destroys the temporary record's owned resources/delegates. It returns `out`. Original allocator wraps bits without sentinel avoidance; creation itself does not reject negative IDs. No locking is established.

All five explicit rejection paths write -1 and return out; they do not allocate an ID or insert. The category log byte threshold >=2 enables their diagnostic, but log gating does not change rejection. Diagnostic reasons in order are no action, empty/invalid handler, missing tag, invalid row, duplicate. Constructors, allocations, delegate operations, provider dereferences and UE logging are not proven exception-safe or gracefully recoverable; do not turn them into synthetic -1 results. Earlier validation can itself call external functionality; static proof does not establish arbitrary reentrant mutations safe. No callbacks are invoked by the entry, although delegated object lifecycle/destruction is not assumed side-effect free.

## Caller boundary and integration limits

`0x1407ed1c0(router, out, widget, descriptor)` is the external routing boundary. Router +98 nonzero immediately returns -1 without calling create. Otherwise it calls create, then requires signed ID >= 0 and successful `0x1407bd730(ID)` global lookup before routing. A negative ID produced after counter wrap has already been inserted by create, but this caller returns -1 without routing; do not silently erase it or change allocation semantics. On accepted ID it performs routing association; result can remain successful even when no suitable route is found. For the observed route calls see `common-button-action-registration-1/HANDOFF.md`; full routing architecture is outside this task.

The production component still needs integration with the actual widget lifecycle, descriptor construction, router association and teardown; this proof does not justify a map-only registration wrapper. Native aliases, runtime scheduling/reentrancy, routing behavior and live end-to-end behavior remain unproven. Record provider and delegate prerequisites are listed above; follow the linked proof boundaries rather than guessing defaults.
