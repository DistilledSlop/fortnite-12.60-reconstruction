Its original PE initialized `.data` value is **1**, and registration flags are **0 / ECVF_Default**. `candidate.inc` supplies a source-shaped registration and getter; names of C++ symbols are placeholders, while console name, help, value, type and behavior are proven. ## Registration and default

The existing CommonInput initializer neighborhood led to `1401c7db0`. The initializer obtains the console manager via the same singleton path as UE, passes name UTF-16 `145a0d640` = `CommonInput.ShowKeys`, address `14783cb80` in R8, help UTF-16 `145a0d5d0` = `Should we show the keys for the current input device.`, and stack flags zero, then calls manager vtable +38 at `1401c7dec`. The result is stored in a static auto-console-object and its destructor is registered. Manager construction `142bcee40` installs vtable `1465c00d0`, whose +38 slot targets `142bca3c0`; that constructs a reference object, stores R8 at +38 and reads a **dword** from it into +40. Its resulting vtable `1465c0888` corresponds to the integer reference implementation. This is the `FAutoConsoleVariableRef` integer registration shape, corroborated by local UE `Runtime/Core/Public/HAL/IConsoleManager.h` and `Private/HAL/ConsoleManager.cpp`; identification is based on actual argument/width and object behavior, not name alone.

The original on-disk PE section table maps RVA `0x783cb80` to `.data` file offset `0x783b980`; those bytes are `01 00 00 00`. Thus 1 is the static initialized value before later configuration or console changes, rather than a default inferred from an already-running process. The five retained runtime captures also each hold 1, which is an observation of those executions only. The replay asserts the section mapping and four bytes directly; it does not hash the executable or whole runtime image.

## Writers and limits

Registration makes the int32 a console-variable reference. Its integer reference vtable +80 is `142bce140`: after priority checks it parses a value into object +40, then invokes `142bb9a30` with the stored reference at +38. The latter writes the dword at `142bb9aac` for ordinary flags; render-thread propagation is the alternate flag-dependent path. Local engine source confirms the corresponding `FConsoleVariableRef<int32>::Set`, `OnChanged` and `OnCVarChange` semantics. Console/config setters therefore remain live; never replace the getter with a constant or an unregistered variable.

A bounded RIP-relative instruction-reference discovery over `[1401c0000,1401c9000)` and `[140795000,140825000)` found the initializer's LEA and getter's CMP as the only aligned relevant instructions targeting this address. This does **not** prove absence of arbitrary indirect writes, outside-range direct writers, console/config overrides, or every engine version's implementation. The directly traced reference setter is an authorized dynamic producer; use the normal engine registration API and its priority behavior rather than emulating writes. No runtime toggle experiment was run.
