# Common action key lookup core

This unintegrated portable core models only the lookup at `0x14081d340`, conditional on the host's settings aggregate and controller resolution. The pinned original image and three instruction windows are recorded in the adjacent JSON; the upstream replay verified the image and twelve windows. The disassembly shows ordered controller selection, the null-object and conditional virtual-resolution path, type and gamepad comparisons, and immediate return from the chosen controller's lookup. Single-key lookup (`0x14081d550`) compares both FName words and returns the first map match. Multi-key lookup (`0x1408190e0`) requires equal counts of at least two and searches for each requested name independently; it does not consume matches, so multiplicity is not enforced.

The adapter must implement the original null/virtual/reload behavior and expose both FName words exactly. It must preserve source ordering and controller/brush lifetimes. The caller owns aggregate preparation, key acquisition, output brush assignment, and actual fallback construction/copy; this core returns a pointer to the matching brush or null and creates no fallback. No UE registration or runtime integration is provided. This is static evidence, not a runtime equivalence claim. Details of the settings preparation, virtual resolution side effects, fallback brush fields, and surrounding refresh remain dependencies described in `/mnt/vibrato/fortnite-work/common-action-widget-brush-contract-1/HANDOFF.md`.
