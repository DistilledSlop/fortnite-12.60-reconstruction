# CommonActionWidget GUI flow diagnostic

Copy the two `CommonActionWidgetFlowProbe` files to `Source/FortniteGame/`, declare and invoke `RegisterCommonActionWidgetFlowProbeDriver()` at startup, and launch a normal GUI client with `-CommonActionWidgetFlowProbe`. The driver waits for a coherent game world, local player and player controller, records ordered `ACTIONWIDGETFLOW` rows, requests exit, and fails the process on a failed observation or timeout. Run `python3 verify.py RUNTIME_LOG`; the verifier requires all 18 rows exactly once, in order, successful. The class names and flag are diagnostic-only.

The probe creates a UWidget within a real player-owned WidgetTree, sets controlled rows and a controller brush, builds its Slate graph via `TakeWidget`, switches two setters while a registry record is borrowed, toggles the registered ShowKeys variable, and releases Slate resources. It verifies the original loaded 421-row table and sends one original handle through the setter. It saves/restores settings, input type, console value and controller data; it explicitly removes its synthetic registry record. It searches for an unused synthetic registry ID before insertion.

Limits: this is controlled startup, not interactive input, pixels, original-runtime comparison, or broad frontend coverage. It observes final setter state and borrowed registry survival, not transient key/array ordering during reentry or garbage collection of a weak owner. It checks the cached brush and Slate image identity/order, not the private image attribute. It deliberately avoids null-subsystem GetIcon calls. No build or runtime pass is claimed until integrated and exercised.
