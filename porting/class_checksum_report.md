### RPC digest: what changed from v1

v1 chained the RPC digest through the super class (`rpc_chain_v1`). CoreNet.cpp does not: each function checksum is seeded with 0, and the export group matches functions by checksum over the class chain. The change is in the definition. Parity flags are unchanged: v1 and the set comparison disagree on 0 classes (v1 fails and the set passes: 0; the reverse: 0).

### Assumptions

- Emitted side = the generated header of each set class: replicated UPROPERTY names, the header's C++ type and array dimension; UFUNCTION(Server|Client|NetMulticast) names. Offsets come from the reflection.
- Emitted UFUNCTION flags are the reflection's (the header's role specifiers are cross-checked against the net bits; table-index flags of properties are cross-checked too).
- Engine and non-set ancestors are not generated: their expected value is their emitted value.
- Struct layouts are the reflection's (the emitted F<Struct>.h is checked for existence only).
- RPC parity uses per-function checksums over the class chain (NetFieldExportGroup); the v1 chained digest is not used for parity. Blueprint-implementable events are not in the reflection's net functions (no FUNC_BlueprintEvent net functions), so no BlueprintEvent case arises.
- Ancestor function names (for NetFields' override exclusion) come from the reflection's per-class function lists; an engine ancestor whose function list is incomplete would change the exclusion.
