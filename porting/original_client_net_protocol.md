# What a replacement server must do for the original 12.60 client

The client is the exact same client as the 12.60 original — feature-complete
and unstripped, rebuilt as a UE project (see `README.md` Goal) — so every
requirement below applies to it as well as to the original binary.

Tags: [log] our Wine client/server logs, [exe] strings in the Shipping exe, [ini] `generated/DefaultEngine.ini`, [src] UE 4.25.0 at `/opt/fortnite/UnrealEngine`. Nothing here has been run against a live handshake yet; items marked (unverified) are inference.

## 1. Handshake and version gating

- **Transport is stock.** `GameNetDriver`/`BeaconNetDriver` = `IpNetDriver` [ini:534-535]; no FortNetDriver/FortNetConnection strings [exe]. `UFortReplicationGraph` exists [exe] but is server-only; it does not change the wire format, so our "ReplicationDriverClass is null" server is fine.
- **Handshake** matches 4.25.0 (227-bit challenge, restart bit, no version field) [src StatelessConnectHandlerComponent.cpp:178; exe strings]. **`net.MagicHeader=1110`** [ini:782] is prepended to every packet. The server must set the same CVar or it drops client packets.
- **PacketHandlerComponents** [ini:2352-2362]: `EncryptionComponent=AESHandlerComponent`, `Components=OodleHandlerComponent` (always-enabled, dictionaries `Content/Oodle/FortniteGame{Input,Output}.udic`, present in pakchunk0). The exe has AES-ECB handler strings only, with no AESGCM or DTLS. AES writes one bit per packet even without a key, so the server must enable the (public, off-by-default) `AESHandlerComponent` plugin. Oodle Network SDK is absent from the public tree (`HAS_OODLE_NET_SDK=0`, Oodle `.Build.cs:77`), so the server cannot compress. Without editing the exe, set `[OodleHandlerComponent] bEnableOodle=False` in the client's loose `Saved/Config/WindowsClient/Engine.ini` and on the server. The component reads it from `GEngineIni` and reserves no bit when disabled [src OodleHandlerComponent.cpp:368,460]. [log] shows that file is applied by the shipping exe.
- **Version check** is server-side, in `NMT_Hello` [src World.cpp:5013]. The client logs `FortniteGame 1.0.0, NetCL: 12896485, EngineNetVer: 15, GameNetVer: 0 (Checksum: 683914758)`. I reproduced 683914758 as UE `StrCrc32` of the lowercased string. Our server logs `FortniteLinux 1.0.0, NetCL: 0, EngineNetVer: 14` (326778485) [log dedicated-server-client-test.log]. A mismatch sends `NMT_Upgrade` and closes. Fix in module startup: bind `FNetworkVersion::GetLocalNetworkVersionOverride` to return 683914758, or bind `IsNetworkCompatibleOverride` to true. Fortnite also has a different format string (`%s %s, EngineNetVer, GameNetVer`, no NetCL), "DeveloperNetworkVersion" and `-net.forcecompatible` [exe]. The log shows the standard formula, but it does not show what Hello actually sends. So log `RemoteNetworkVersion` on the first connection and prefer the compatible-override.
- **Flow:** Hello, then Challenge, Login, PreLogin, Welcome (client loads the map from its own paks), Join. Login URLs can be huge; this tree already has the 16 MB patch [src World.cpp:5076]. The client's MCP `UniqueNetId` cannot be built without an MCP OSS, but `operator<<` ignores that failure [src OnlineReplStructs.cpp:47-52], so login proceeds.
- **Encryption token.** The client fetches a key from `GET /api/game/v2/matchmaking/account/{acct}/session/{sid}` (FortMcpUtils, base64 key in a JSON object; field name unverified) and adds `?EncryptionToken=` to the join URL. The server must bind `FNetDelegates::OnReceivedNetworkEncryptionToken` [src World.cpp:5031] and return the same 32-byte key, else `NMT_Failure "Encryption failure"`. `Fort.UseFakeEncryptionKey` does not work in shipping [exe]. A direct connect without the option skips encryption.

## 2. Replication strictness

- Live connections use **positional** handles, not names. The checksum-per-property path is only for demo/InternalAck connections [src RepLayout.cpp:794,3313]. So for every replicated class the server must match: super chain, replicated UPROPERTY order (native: declaration order; BP: memory offset [src Class.cpp:4079]), array dims, struct layouts, custom `NetSerialize` bit formats, and the set of net UFUNCTIONs (sorted by name, so RPC indices shift).
- Each class export carries `FClassNetCache::ClassChecksum`: a cumulative CRC over lowercased property name, C++ type, array dim and struct fields [src CoreNet.cpp:48-92,238]. The client compares it in `GetObjectFromNetGUID` [src PackageMapClient.cpp:3176] and raises `ENetworkFailure::NetChecksumMismatch` ("Network checksum mismatch. FullNetGUIDPath…" [exe]). The log prints both values, which is useful for diffing.
- **Client relaxers**, via loose `[ConsoleVariables]`/`[SystemSettings]` (all strings present [exe]): `net.IgnoreNetworkChecksumMismatch=1` (stops the disconnect only; mis-sized layouts still desync), `net.AllowEncryption=0`, `networkversionoverride=`, `net.MagicHeader`. Whether shipping honors each cvar is unverified.
- **Unknown classes are not fatal but wrong.** A class path absent from the client fails archetype/class resolution and the actor is dropped [src PackageMapClient.cpp:595, DataChannel.cpp:2624]. Our invented `AApolloLandscapeTile`, `AApolloBackgroundMesh`, `AApolloSkyAtmosphere` and `AApolloSunLight` must not replicate to the original client.
- **Required classes** (all native names must be exact):
  - Every map: `FortWorldSettings`, which is a replicated actor (`AWorldSettings` has 5 replicated properties) and is currently an empty subclass.
  - Apollo_Terrain: `FortPoiManager`, `FortWorldManager`, `WorldTileManager`, `FortLevelScriptActor` [map-native-imports.jsonl].
  - Athena join: `FortGameModeAthena` (server-only), `FortGameStateAthena`, `FortPlayerStateAthena`, `FortPlayerControllerAthena`, `FortPlayerPawnAthena`, `FortAthenaMapInfo`. Also inventory/quickbar actors, mutators, aircraft and safe zone (names inferred from [exe]; none is in the 146 map imports).
  - Blueprint subclasses live at `/Game/Athena/Athena_GameState`, `Athena_GameMode`, `Athena_PlayerController`, `PlayerPawn_Athena`. The server can replicate the native parent path instead, which keeps the wire valid but loses BP components.
- Stock engine classes (PlayerController, PlayerState, GameStateBase, Character) exist on the client. If the 12.60 engine fork changed their replicated sets, the mismatch shows up immediately in the checksum log.

## 3. Lobby to match (from [exe]; response schemas partly inferred)

1. `GET /fortnite/api/game/v2/matchmakingservice/ticket/player/{id}?partyPlayerIds=&bucketId=&player.platform=&player.subregions=` returns JSON with `serviceUrl`, `ticketType`, `payload`, `signature`. The client opens a websocket to `serviceUrl` with an `Epic-Signed` header.
2. Websocket messages named `StatusUpdate` with state `Connecting`/`Waiting`/`Queued`/`ReadyCheck`/`SessionAssignment` (fields `totalPlayers`, `connectedPlayers`, `queuedPlayers`, `estimatedWaitSec`, `ticketId`, `matchId`), then a play message (`HandlePlayMessage`) carrying `sessionId` and `joinDelaySec`.
3. `GET /fortnite/api/matchmaking/session/{id}` returns the OnlineSessionMcp record: `ownerId, ownerName, serverName, serverAddress, serverPort, maxPublicPlayers, openPublicPlayers, publicPlayers, privatePlayers, attributes, buildUniqueId, started`. `buildUniqueId` defaults to the network-compatible changelist (`bUseBuildIdOverride=false` [ini]), 12896485 for this client; this is distinct from the network checksum 683914758. The client build-ID reader at 0x140d6a010 and its fallback at 0x142c98b90 confirm the value.
4. Then the key request above, then beacons: party beacon reservation, lobby beacon, ClientTravel, reconnect after map load ([exe] "Cancelling between reservation connect and lobby connect", `ClientReconnectResponse`). `BeaconPort` is a session attribute. This needs `AFortPartyBeaconHost`/`AFortLobbyBeaconHost` layouts on a second net driver. Whether a bare ClientTravel can bypass it is unverified.
5. Party creation needs XMPP, not just HTTP [ini: bEnableXmpp], which is a large extra backend. Alternative with no backend: `-nomcp` exists [exe]; and `UGameInstance::StartGameInstance` browses a first command-line token such as `127.0.0.1:7777` [src GameInstance.cpp:566-575]. `ExecCmds` is compiled out of Shipping [src UnrealEngine.cpp:1578].

## 4. Staged plan

| # | Step | Feasibility |
|---|------|-------------|
| 0 | Server: MagicHeader, AES plugin, Oodle off (server and client ini), network-version override, `net.MaxChannelSize=65535`; log remote checksum | High |
| 1 | Direct connect (`ip:7777` or `-nomcp`) to `FortniteEmptyDedicated` with stock engine classes. Success: Welcome, client loads the map, `Join succeeded`, stays connected past the 90 s timeout | Medium-High. Risk: FortGameInstance/FortLocalPlayer casts, crash instead of disconnect |
| 2 | Compare engine-class checksums in client and server logs; use `IgnoreNetworkChecksumMismatch` only for diagnosis | Medium |
| 3 | Recover exact FortniteGame reflection (parent, replicated property order/types, net functions, struct NetSerialize) from UHT data in the exe's `.rdata` plus cooked BP properties (`cue4inspect --function-report`). Rebuild `FortWorldSettings`, `FortGameStateAthena`, `FortPlayerStateAthena`, `FortPlayerControllerAthena`, `FortPlayerPawnAthena`, `FortAthenaMapInfo`, then inventory/quickbar, then Apollo managers. Replace the invented Apollo actors with original classes or client-only conversion | Low-Medium, large |
| 4 | Server loads Apollo_Terrain plus the 87 streamed levels, so static NetGUID paths match. Blocked by cooked-BP load crashes (README) | Low |
| 5 | Backend: ticket, websocket, session, key endpoints, then beacon hosts; XMPP last | Medium; beacons and XMPP Low |

**Status from the direct-connect runs** (`direct_connect_results.md`; observed, not inferred):

- Step 0: the client logs `LogNetVersion: FortniteGame 1.0.0, NetCL: 12896485, EngineNetVer: 15, GameNetVer: 0 (Checksum: 683914758)` and loads `net.MagicHeader:1110` from its loose config. The server logs `net.MagicHeader = 1110`, `net.MaxChannelSize = 65535`, and `Network encryption key not configured.` The server's `LogNetVersion` line still reports checksum 326778485. The override's `Local network version checksum: 683914758` line has not appeared, because no NMT_Hello reached the server. Step 0 is partly observed.
- Step 1: not reached. The client never sent NMT_Hello. The blocker is the login gate: with no `-AUTH_*` flags the frontend shows manual sign-in (`LogFortLogin: Could not auto-login. Starting manual login process`, `LogAppES: postponed 2`), and `-nomcp` and `-MeshParent=127.0.0.1 -MeshParentPort=7777` (both accepted on the command line) do not skip it. A bare `ip:port` first token is rewritten to `-ip:port` by UE's command-line whitelist. A loose `GameDefaultMap` cannot hold an address (`FSoftObjectPath`), and `-ini:` overrides are compiled out of Shipping. The earlier "server stall" was a harness bug, not a server fault: the runner checked TCP (`ss -ltn`) for a UDP listener. The server listens about 7 ms after its Browse (`LogNet: GameNetDriver IpNetDriver_2147482579 IpNetDriver listening on port 7777`). Details in `direct_connect_results.md`.

**Module changes:** in `FortniteGame.cpp` StartupModule bind the version overrides and `OnReceivedNetworkEncryptionToken`. Gate `AFortGameModeAthena::StartPlay` Apollo spawns behind an "original client" flag. Add `GeneralProjectSettings ProjectVersion=1.0.0`. Add the AES plugin to the uproject. Add `[SystemSettings] net.MagicHeader=1110` and the PacketHandlerComponents section to `native/Config/DefaultEngine.ini`.
