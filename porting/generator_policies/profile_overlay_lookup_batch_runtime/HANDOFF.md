# Derived profile overlay lookup

This bounded source proposal implements `0x1410fbda0` recomputation and `0x1410fe220` derived group lookup using the canonical `FMcpProfileItemPtr`, `FMcpProfileItemArray`, `FMcpProfileGroupMap`, and `FMcpProfileItem` fields. Evidence is the original image `/mnt/vibrato/fortnite-evidence/original-late-capture-1/image-125.runtime.bin`, base `0x140000000`, SHA-256 `338c83a2314ccac1040a2c0bb520b893013cc7b58eda58e550da67f5d84de680`, and the bounded probes and details in `profile_backend_installation_runtime/HANDOFF.md`. The source names and signatures are assigned integration names, not recovered symbols or layout.

Recompute empties the caller's output, returns zero for a missing base array, and otherwise preserves base order. It uses case-sensitive item IDs to find replacements, counts every match, includes a positive-quantity replacement and omits a nonpositive replacement. Unmatched base pointers are copied. As in the binary, base and replacement item pointers are assumed valid. A match count of zero selects the original base array; a nonzero count caches even an empty result. The cache assignment copies shared pointers and owns its references independently of the temporary. Lookup returns a borrowed base/cache array or null if the base is absent; the owning backend's destruction or relevant mutations invalidate borrowed results.

`FMcpProfileGroupMap` and `TSet<FString>` use the same default folded FString key behavior already established for canonical base maps (ASCII fold with unequal non-ASCII UTF-16 units compared directly). Overlay map equality is explicitly case-sensitive; its ordinary FString hash can merge case variants into a hash bucket but equality distinguishes them. The default key behavior and UTF-16 target evidence are documented in `typed_profile_backend_runtime/HANDOFF.md`. Do not substitute the default case-insensitive map equality for the overlay map.

Integration requires adding the declarations to `UMcpProfile`, making `ProfileOverlayState.h` visible there, and compiling the bodies with the existing canonical bridge. `FMcpProfileOverlayState` is only the recovered partial state of the *same actual derived backend* that owns `BaseGroups`, not a second overlay/cache and not a full backend owner. The actual owner, population, overlay writers, dirty marking, and GC traversal remain unclosed. Connect those real paths to these same fields before claiming complete behavior. The helper consumes the provided backing state and does not reconstruct or install that owner. No canonical/generator files, builds, tests, runtime execution, or commits were changed/run.
