# Pickaxe VFX getter integration

The generator and behavior manifest wire this policy to the two reflected pickaxe getters. `Private/FortPickaxeVFXRuntime.{h,cpp}` implements their shared lookup. Regenerate through `porting/promote_native_classes.sh`; do not edit generated output directly. The policy rejects changes to the original struct members/offsets or getter signatures/flags. The virtual declarations retain polymorphic overrides. Original execs are `0x142b4f770` / `0x142b4f960`; implementations are `0x141a798a0` / `0x141a7c6c0`.

Original helper 0x141dcce60 invokes native `IFortVFXDataOwner` first, then `TPropertyValueIterator<FStructProperty>` with recursion=0 (`NoRecursion`) and deprecated=1 (`IncludeDeprecated`). This uses engine property iteration order, includes static property array elements but does not descend into dynamic arrays or nested structs; a `RuntimeMarshalledData` dynamic array alone is therefore not a fallback match. The native interface method is provided as a pure virtual contract; no generated native implementers have yet been wired. The original selector iterates `DynamicSystems`, requires a corresponding weak-key tag map entry, and uses hierarchical `HasAll` matching. The two getter tags come from `FFortNativeGameplayTagsRuntime` original singleton offsets. Fallback applies only after no eligible match.

The original marshaller's component registration/removal producers remain unimplemented. An empty `ComponentTags` map has faithful empty-registry behavior, but managed components will not be discoverable until those producers are reconstructed. This proposal does not fabricate entries.
