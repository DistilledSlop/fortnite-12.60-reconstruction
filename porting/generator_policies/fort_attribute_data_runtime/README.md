# Complete native attribute data lifecycle

The production generator restores the original `FFortGameplayAttributeData` constructor and both virtual setters. The generator activates the hooks below; build and runtime acceptance are recorded on the canonical wiki.

Integration: load `source_policy.py`; call `add_roots(gate, seeds)` alongside other native struct policy roots, `apply_struct(info, model)` in `TypeGate.build_struct`, `declarations(model)` inside the struct, and `footer(model)` after the struct. Also append `struct_includes(model)` in `render_struct_header` to supply `xmmintrin.h`; the emitter resets model includes, so this rendering hook is required. The upper clamp uses `_mm_min_ss` on the supported Linux/Windows x86_64 targets. Regenerate through the existing workflow. The policy pins the entire original reflection record, native parent, size/alignment, original declaration order, native bool types, and recovered offsets. It fails closed on drift.

The original 40-byte object has base/current at +8/+12, Minimum/Maximum at +16/+20, three **separate native bool bytes** at +24/+25/+26, then unclamped base/current at +28/+32. Kind `0x2c` includes NativeBool despite extraction's misleading `bitfield: true` annotation. The three SetBitFuncs prove distinct byte stores; generated fields must stay ordinary bools. Static assertions check every reflected member, total size and alignment.

`0x142840060` is the exact struct-ops constructor: base/current/unclamped values +0, bounds -FLT_MAX/+FLT_MAX, all bools false. Its native vtable at `0x145ef12c0` is destructor `0x141b5c720`, current setter `0x141bc4960`, base setter `0x141bc47e0`. There is no additional virtual clamp operation. The inherited virtual destructor suffices: the original destructor only restores the engine base vptr and optionally frees storage. Original struct-ops copy `0x142840460` copies every data member, excludes vptr/padding, and returns true; default member assignment with `WithCopy=true` implements this. Ops traits have no Serialize, NetSerialize, PostSerialize, PostScriptConstruct, Identical, or mismatched-tag hooks. No hook is invented.

Both setters compare input with the prior **unclamped** value and return when equal **or unordered**. Consequently +0/-0 is unchanged; any incoming NaN is ignored; a previously stored unclamped NaN prevents further setter updates. A bounds/flag change alone does not re-clamp equal input. The current setter always clamps; the base setter clamps only when `bShouldClampBase` is true. Each updates its own unclamped value, inherited value, and own clamped flag; neither invokes the other setter. Constructor does not call setters.

The clamp takes Minimum when `Input < Minimum` or Minimum is NaN. Otherwise it computes the original `MINSS(Maximum, Input)` behavior: Maximum only when ordered strictly smaller, Input for ties (signed zero preserved) and a NaN Maximum. Clamped flags are true for **ordered unequal** output/input; NaN output produces false. The upper clamp executes literal `_mm_min_ss(Maximum, Input)`, retaining original SSE handling of subnormals when DAZ/FTZ is enabled. A scalar comparison/selection initially passed ordinary values but failed under DAZ because MINSS flushed a selected subnormal Maximum; the intrinsic fixes that verified regression. No arithmetic, epsilon, integer conversion, canonicalization, or finite sanitization occurs. Integer bit tests in the proposal explicitly retain NaN handling. Exact instruction-level floating exception flags/trap behavior is not claimed: source ports preserve stored values and branches under the normal masked SSE environment.

Raw ASM snapshots and original bytes/hashes are tracked here; exact-address decompilations and rendered review header are in ignored `porting/generated/agents/fort-attribute-data-runtime22/`. Ghidra decompilation's plain `!=` is wrong for the original `UCOMISS; JE` NaN behavior; ASM controls. `rd.py` also heuristically resolves these small addresses to unrelated preceding functions; exact capture was required.

Verification: `python3 porting/generator_policies/fort_attribute_data_runtime/verify.py` validates the pinned reflection and original bytes/vtable, checks five fail-closed drift mutations, renders an isolated header, and executes original leaf setters in isolated executable memory against a bit-preserving oracle. All 4,356 combinations passed: current/base, both clamp flags, finite limits, inverted limits, infinities, both signed zeros, qNaN/sNaN input/prior value/lower and upper limits. It checks all 40 bytes, including unchanged sibling fields, vptr and padding. No game build or runtime mutation was used. The actual emitted policy declarations (including Set*.inc bodies) are also compiled into a standalone 40-byte virtual-base harness with the bundled server clang 9.0.1, actual server response-file float flags `-O2 -fno-math-errno`, and an additional `-O2 -ffast-math` control. Both variants match original machine code for all 69,360 cases each, comparing all 40 bytes and adding positive/negative subnormals, minimum normal values, four SSE rounding modes, and DAZ+FTZ. Generated sources, compiler logs and compiled-verification.json are in the ignored artifact directory. This is a minimal standalone build; normal engine generation/UHT/build checks remain with root. Live HUD/movement behavior is outside this evidence and must be tested separately; shared attribute lifecycle as their root cause remains a hypothesis.
