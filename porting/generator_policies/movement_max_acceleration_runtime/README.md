# GetMaxAcceleration recovery

`GetMaxAcceleration.inc` is the complete 0x1420e1760 base override; `GetAirControlLevel.inc` is helper 0x1420e2690. Both bodies are admitted by the global behavior manifest together with `air_selector_admission_runtime`. `source_policy.py` upgrades the existing AFortPawn movement-style helper to virtual, without adding a duplicate, and checks its exact existing snippet and signature. It validates the query helpers, the selector dependency, water property, pawn ability interface, signatures and rendered bodies. The generator calls `apply(model)` after splicing and `finalize(model, header, cpp)` after rendering. Use the ordinary engine virtual inference plus the proposed manifest entries; preserve the original derived Athena override as separate work.

Original branch order and contracts:

1. Custom modes 3, 4, 9, 5, 12: `GetAirControlParams().MaxAcceleration.GetValueAtLevel(GetAirControlLevel(), nullptr)`. Mode 5 uses the constructed default parameter block. The level helper returns the balloon count converted to float only for mode 9 with PawnOwner (original +0x130) cast to AFortPlayerPawn; otherwise exactly 0. It invokes the existing nonvirtual GetNumActiveBalloons, whose original helper zero-extends the reflected count byte.
2. Custom mode 10: if CharacterOwner casts to AFortPlayerPawn, invoke the existing movement-style helper virtually and compare the byte at its returned pointer to `EFortMovementStyle::Sprinting` (3). True selects `SurfaceSwimmingWaterControlParams.MaxAccelerationSprinting`, otherwise `MaxAcceleration`; evaluate at 0.0f with null context. Reflection gives struct base +0x1558 and members +0xa0/+0xc0. The virtual contract, native descendant slots and reflection evidence are in `generated/agents/movement-accel-virtuals8/REPORT.md`.
3. Custom mode 6: original unconditionally dispatches through CharacterOwner's Fort ability interface, which has a valid-owner contract. The body uses the existing AFortPawn virtual getter, casts its result to UFortAbilitySystemComponent, and requests the first matching `UFortJumpBoostSet`; if present it returns `LateralAcceleration.GetCurrentValue()`. Missing ASC, wrong ASC class or absent set falls through. The local Engine GetSet walks attributes in the same order and tests IsA, matching original 0x1406c7d70. See `generated/agents/movement-accel-owner-contracts11/REPORT.md`.
4. For an AFortCharacterVehicle_Ostrich owner, call `IsMovingOnGround()` virtually (original +0x550); when true return `AccelFromIdle` if `bAcceleratingFromIdle` is true and that value is strictly positive. Otherwise call `UCharacterMovementComponent::GetMaxAcceleration()`. Both owner fields already exist and the byte identity has a reflected setter proof. Original addresses are evidence only, not regenerated object offsets.

`test_generator_admission.py` overlays both this proposal and the independent selector manifest in memory and generates only into ignored `generated/agents/movement-max-acceleration7/`. Real AFortPawn and movement models passed admission and render checks, as did negative checks for modified ancestry, signature, body, and duplication. It is an isolated generator check, not a build or runtime test. Full physics also depends on the separate PhysCustom shared-flag producer and the Ostrich vehicle update, which this query does not implement. Admission tests also accept uniquely present identical global entries while rejecting changed metadata or duplicate keys. Native build and runtime results are tracked on the canonical wiki.
